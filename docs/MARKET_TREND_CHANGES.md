# 시장 설명과 추세 관측 변화

홈과 추세추종은 `trend_following.market_explanation`의 같은 자료를 사용한다. 지수 방향(종가·50/200일 배열·200일선 기울기), 기업 참여(50/200일선 위 기업 수/각각의 유효 분모), 지수 변동성(20개 일수익률 표본 표준편차의 연율)을 분리한다. 상승 정렬이면서 참여가 약하면 지수 수준과 관찰기업 참여가 다른 혼합 신호임을 설명한다. 전체 시장·수급 또는 공식 신호등의 독립 검증으로 표기하지 않는다. 화면 필터는 참여 분모에 영향을 주지 않는다.

`build_trend_following`은 읽기 전용이며 기본 `changes.status=no_prior`를 제공한다. 기존 서버의 완료 관측/루트 캐시 생성 경로에서만 `observe_trend(data, project_root / '.local' / 'trend-checkpoints')`를 호출하고 반환값을 `data['changes']`에 둔다. `.local/`은 기존 공유 제외 경로다. 새 예약·조회·네트워크·주문을 추가하지 않는다. 저장 실패는 조회 결과와 구분해 알리고 기록 성공으로 표시하지 않는다.

기록은 가격 기준일, 자료 모드, 종목의 거래소/코드/이름, 당시 RS와 모집단 수, 고정 시총1,000억원·RS70 조건, 당시 기본 순위와 종가/단순 상태의 파생 요약만 저장한다. 원가격 시계열·대량 차트·개인 보유는 저장하지 않는다. SHA-256과 날짜별 수정본을 붙인 배타적 생성으로 과거 결정을 덮어쓰지 않는다. 같은 데이터 재조회는 기록을 추가하지 않고 기존 이전 관측과의 비교를 유지한다. 같은 날짜 자료 수정은 별도 수정본으로 남긴다. 자료 모드는 경로를 분리한다. 첫 조회에는 전일을 추정하지 않는다. 과거 체크포인트가 있으면 정확히 그 관측일을 표시하며 인접 거래일이라고 단정하지 않는다. 미래 관측을 이전 기준일 비교에 사용하지 않는다.

기본 조건 신규/이탈과 돌파선3% 이내·20일 최고종가 돌파·50일선 아래 상태를 보여준다. 기본 조건 후보의 현재 상태와 이전 기본 후보의 악화 상태를 함께 관찰한다. 종목 이름/거래소가 바뀌거나 관찰대상·자료가 없어지면 현재 자료/대상 확인 대기로 분리하고 가격조건 이탈로 확정하지 않는다. 돌파는 종가 기준이며 거래량 동반 여부를 별도로 표시한다. 기록은 관측 변화이며 백테스트 또는 전일 유니버스 재구성이 아니다.

관심목록은 사용자가 종목 카드에서 추가하며 이 브라우저의 자료 모드별 로컬 저장소에 보관한다. `현재 점검 저장`을 눌렀을 때만 당시 파생 상태를 보존한다. 필터 변경과 새로고침은 관심목록/과거 점검을 바꾸지 않는다. 같은 상태의 중복 저장은 추가하지 않고 같은 날짜 수정은 다른 수정본으로 남긴다. 관심 해제 뒤에도 기존 점검 이력은 유지한다. 브라우저 저장 불가 시 명시하고 서버 기록과 구분한다.

내보내기 연결: `market_explanation_ui.js`, `trend_changes_ui.js`를 `trend_following_ui.js`보다 먼저 포함하고 `market_explanation.css`를 포함한다. 홈 HTML은 `MarketExplanationUI.render(data.trend_following.market_explanation)`로 생성한다. 추세 UI는 두 도우미가 있으면 같은 설명과 변화/관심 패널을 직접 연결한다. 기존21개 미리보기·페이지6개·동시2개 lazy 차트 계약을 유지한다.

검증: `python -m unittest tests.test_market_trend_changes tests.test_trend_following`, `node tests/test_market_trend_changes.js`, `node tests/test_trend_following.js`, `python tests/test_market_trend_changes_ui.py`. 합성 자료만 사용하며 실제 운영 서버/원자료/DB를 변경하지 않는다.
