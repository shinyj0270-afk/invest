# 포트폴리오 실데이터 입력 검증

포트폴리오 탭은 계산 전에도 입력 후보 수·편입 조건 충족 수·제외/확인 필요 수를 표시한다. 보유 판단 엔진의 HOLD 조건, 가격 기한, 산업과 공통 위험군 입력을 함께 검사한다. 조건이 부족한 후보를 임의로 채우거나 자료 없음 결과를 현금 100% 의견으로 바꾸지 않는다.

기존 알고리즘을 유지한다: 최대 5개 **기업**, 기업/산업/공통 위험군 상한, 최소 현금, 사용자가 확인한 하락 시나리오 기준, 고정 슬롯 균등배분. 최대 기업 수와 상한 값은 개발용 기본 가정이며 실제 수익률·최적 배분을 검증한 것은 아니다. 동일 기업의 여러 종목은 중복 편입하지 않는다.

## 저장자료 재검사

```powershell
.\.venv\Scripts\python.exe tools/verify_portfolio_data.py --snapshot private_data/infomax/snapshot-review.json --output validation/portfolio-check.json
```

사용자 보유·검토 입력 및 실제 사용할 구성 설정이 있으면 `--holdings private_data/holdings.json --policy private_data/portfolio-policy.json`을 추가한다. 도구가 검토 상태나 설정 확인을 대신 채우지 않는다. 평가일은 기본적으로 현재 KST 날짜다. `--as-of`로 다른 날짜를 지정하더라도 해당 시점의 자료 이용 가능성을 인증하거나 백테스트 검증으로 취급하지 않는다.

기존 파일은 덮어쓰지 않는다. 반복할 때는 새 결과 파일명을 지정하거나 `--output` 없이 화면에서 결과를 확인한다. 입력 원자료·보유내역·설정과 결과는 PC 로컬 제외 폴더에 보관한다. Node.js와 이 PC의 Python 가상환경을 사용한다. 네트워크·계좌·주문 연결은 없다.

## 결과 읽기

- `verification_status=passed`: 입력 처리와 배분 제약 검사가 통과했다는 뜻이다. 자료 준비나 투자 성과 검증과 다르다.
- `portfolio_status=SETTINGS_REQUIRED`: 모의 구성 설정 확인이 필요하다.
- `portfolio_status=DATA_REQUIRED`: 가격·연구 근거·분류 등이 부족하다. 선택 종목은 없으며 현금 목표도 `null`이다.
- `MODEL_PROPOSAL`: 입력된 검토 조건으로 계산한 모의안이다. 선택 기업 수·비중 합계 100%·기업/산업/위험군 상한·최소 현금·입력 하락 시나리오 산식을 별도로 검사한다.
- `CASH_ONLY`: 자료 부족과 구분되는 모형 결과다. 검토상 부적격이거나 설정된 배분 제약 때문에 편입이 없을 수 있다.

이번 실제 저장자료의 3종목은 투자 논리 검토·공통 위험군이 없고 가격도 오래되어 편입 준비 0개다. 검증을 통과시키려고 HOLD를 입력하지 않는다. 5종목을 실제로 구성할 수 있는지는 최신 가격과 사용자 검토·위험군이 갖춰진 다음 확인한다. 5종목 상한과 배분 경계는 별도의 명시적 가상 시나리오로 검사한다.
