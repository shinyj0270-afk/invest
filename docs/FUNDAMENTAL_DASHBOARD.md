# 국내 기업 발굴 중심 통합 대시보드

## 최종 포맷 방향 · 사용자 확정 2026-10-02

최종 목표는 [스탁이지](https://stockeasy.intellio.kr)의 화면 구성과 탐색 흐름을 참고해 사용자의 투자 방식으로 바꾼 개인 통합 대시보드다. 현재 여러 분석 화면을 나열한 구성은 중간 단계다. 기능 추가보다 복잡한 정보를 쉽게 읽고 적은 조작으로 다음 판단에 도달하도록 만드는 것을 우선한다.

- 기본 흐름은 시장·관심기업 한눈에 → 수익성·재무 체력·가격으로 기업 찾기 → 기업 핵심 요약·재무·추세 확인 → 관심·보유·최대5종목 구성 검토다.
- 홈에서는 필요한 요약과 다음에 확인할 기업을 먼저 보여주고, 기업을 누르면 핵심 수치·동종 비교·가격 차트가 한 흐름으로 이어지게 한다. 원수치·계산식·설정·파일 관리는 펼쳐 보는 영역으로 둔다.
- 여러 지표를 별도 메뉴로 계속 늘리지 않는다. 주요 업무 중심으로 메뉴를 묶고 같은 자료·행동을 중복 노출하지 않는다. 메인 버튼은 새로고침 하나로 유지한다.
- 일별 종가는 앱을 열 때와 열린 동안 자동 갱신하고, 새로고침은 최신 제공 가격을 조회한다. 완료 종가와 장중 참고 가격·조회시각은 쉽게 구분한다.
- 수익성/재무/가치 중심의 국내 기업 발굴을 우선하고, 추세와 RS는 확인 도구로 사용한다. 관심·보유·매입가·현금·연구는 사용자의 직접 입력과 기존 비공개 동기화 계약을 유지한다.

2026-10-02 화면 개편에서 주요 메뉴6개, 홈 시장/관심/보유/산업 요약, 기업 분석의 상세 이동, 판단 근거 접기를 구현했다. 상세 기능 범위와 데이터 검증 원칙은 아래의 기존 합의를 따른다. 원본 전략·AI 브리핑·수급은 자료 미연결 상태를 유지한다.

## 합의된 범위

현재 수익성·재무 체력이 우수하고 펀더멘털 대비 가격이 저렴한 국내 기업을 찾는 것이 주 목적이다. 기업별 수치를 짧게 읽고 추세추종 관점의 기술적 분석으로 이어진다. 보유 유지·매도 검토와 5개 이하 포트폴리오는 보조 기능이다.

ETF, 미국장, AI 리서치/대화, 동일 전략 추천·수익률 복제, 전체 사이트 저장, 실시간 시세는 제외한다. 스탁이지의 일반적인 조건검색·종목 요약·관심목록·산업 비교·추세 화면 구성은 기존 코드와 데이터로 구현한다.

## 화면과 판단 기준

포트폴리오는 사용자 결정(2026-10-02)에 따라 Codex가 작성하는 월간 추천 목표안으로 확장한다. 특별한 편입 후보는 월중 수정 가능하며 이유와 이전안 대비 변경을 보존한다. 기존 계산기는 보조 검증 도구다. 자세한 운영 기준과 현재 작성 대기는 [추천 포트폴리오 운영 기준](RECOMMENDED_PORTFOLIO.md)을 따른다.

1. **기업 발굴:** 시장·산업·기업명, ROE·영업이익률·매출 성장률 하한, 부채비율·PER·PBR 상한, 추세 조건. 모든 기준은 사용자 입력이며 기본값은 비어 있다. 결측은 활성 조건을 통과하지 않는다. 표는 페이지를 나누되 필터와 CSV는 전체 적격 모집단에 적용한다.
2. **간단 분석:** 수익성, 재무 체력, 가치평가, 추세의 사실을 구분한다. 동일 산업·재무 기간·연결/별도 기준의 비교값과 표본 수를 표시한다. 소수 비교군과 결측으로 저평가를 단정하지 않는다.
3. **추세 확인:** 검증된 확정 수정종가와 50/150/200일 이동평균, 종가 기준 52주 최고와의 거리, 기존 추세 조건·거래량 돌파·변동성 축소. 이력이 부족하면 부족 이유를 표시한다.
4. **관심목록:** 브라우저 메모리에서 관리하고 명시적으로 JSON 저장/불러오기를 지원한다. 새 가격으로 새로고침할 때 같은 탭에서만 복원한다. 기업 식별이 달라지면 제외하고 알린다.
5. **산업 비교:** 저장된 적격 기업의 산업별 규모·유효 수치 중앙값. 전체 시장 상승률이나 시장 전체 강도로 표현하지 않는다.
6. **공시·뉴스:** 이미 저장된 공개 메타데이터만 읽는다. 기준일 이후 기사·공시는 제외하고 원문 링크를 제공한다. 개인 검토 기록은 HTML에 넣지 않는다.
7. **보유·포트폴리오:** 기존 엔진의 1~5개 제한과 보유/감축/매도/판단대기 검토를 재사용한다. 단순 PER/PBR이나 차트 필터 통과를 자동 주문·매도 지시로 바꾸지 않는다.

## 확정한 RS 구성

|항목|기존 구현|스탁이지 공개 설명|
|---|---|---|
|핵심 수익률|126/252거래일 종목 수익률에서 해당 시장 지수 수익률 차감|12개월 가격수익률을 분기 단위로 반영하고 최근 분기에 2배 가중|
|종합 순위|입력된 적격 종목의 6개월 백분위 60% + 12개월 백분위 40%|전체 종목 대비 0~99.99 상대 순위|
|보조 기간|126/252거래일 초과수익률|1·2·3·6개월 RS|
|확인 가능한 한계|입력 종목 범위에 따라 순위가 달라짐|정확한 동률·결측·신규상장·분기 계산 세부는 공개 문구만으로 확정 불가|

출처: [스탁이지 RS 안내](https://stockeasy.intellio.kr/guide/rs), `investment/trend.py`. 사용자가 **가격 추세 순위 주지표 + 지수 대비 초과수익 보조지표**를 선택했다. 새 화면에서 6/12개월 초과수익률은 %p로 명시한다. 기존 연구용 추세 판정식은 유지한다.

대시보드 가격 추세 산식: 최신부터 63거래일씩 4개 독립 분기 수익률 q0~q3를 구하고 `(2*q0 + q1 + q2 + q3)/5`로 가중한다. 252거래일을 약 12개월로 사용하는 자체 구현이다. 같은 거래소·같은 기준일의 유효 저장 적격 기업에서 동률 중간 백분위 `100*(낮은 값 수 + 0.5*동률 수)/유효 수`를 계산하며 상한은 99.99다. 최소 5개 기업이 필요하다. 확정 분할수정 종가 253개와 검증 거래일을 요구하며, 화면 검색·필터는 이미 계산된 순위 모집단을 바꾸지 않는다.

표시되는 순위는 **저장 유효 기업 내 순위**다. 스탁이지의 전체 시장 RS와 같은 값이라고 주장하지 않는다. 모집단 수·거래소·계산식을 함께 표시한다.

## PER/PBR 데이터 원칙

공급자 값 또는 확인된 EPS(TTM)/BPS와 호환되는 가격으로 계산한 값만 사용한다. 가격일·공개일·재무 기간·거래소·연결/별도·주가 조정 기준을 보존한다. 분모가 0/음수인 PER/PBR은 저평가 수치로 쓰지 않는다. Infomax를 우선하며 서로 다른 기준 자료를 임의 결합하지 않는다. 현재 저장 파일에 필요한 항목이 없으면 입력 대기로 남는다.

## 검증 범위

순수 필터·정렬·비교군·관심목록 검증, 미래/결측/음수 가치평가, 확정 가격·거래일·이동평균의 선행정보 배제, HTML 원본 스냅샷 보존, 기존 포트폴리오 회귀, 브라우저 메뉴·필터·CSV·관심목록·모바일을 확인한다. 실제 원자료·DB·PC 설정을 테스트 자료로 변경하지 않는다.

## 네이버 증권 활용

사용자 요청으로 [네이버 증권](https://stock.naver.com/)을 보완 출처로 연결했다. 공개 종목 화면의 상세 응답에서 PER/PBR/EPS/BPS·관측 가격과 시각을 한 번 조회해 PC 로컬 캐시에 저장한다. 현재 005930·000660·005380의 실조회가 성공했다. 2026-09-30 장중 참고값이며 기존 2026-09-23 인포맥스 스냅샷을 덮어쓰지 않는다.

```powershell
.\.venv\Scripts\python.exe tools/naver_reference.py --codes 005930 000660 005380
```

- 기본 캐시: 해당 PC `data_dir/<profile>/references/naver_reference.json`. Git 제외. 명시한 1~30종목만 한 번 조회하며 예약·실시간 반복 조회는 없다.
- 라이브 서버, CLI 내보내기, Streamlit HTML 생성에서 캐시를 읽어 **기업 간단 분석 → 네이버 증권 · 보완 자료**에 표시한다. 읽기만으로 새 웹 조회를 하지 않는다.
- 정확한 재무 분기, CFS/OFS, 수정주가 기준이 응답에 없다. 네이버 안내의 EPS/BPS 주식수 정의는 보통주·우선주 합산이므로 현재 인포맥스 관측 계약으로 자동 승격하지 않는다. 추정 PER/EPS는 실적 PER/EPS를 대체하지 않는다.
- 0/음수 EPS 또는 BPS는 각각 PER/PBR 비교에서 제외한다. 원천의 비율과 분모가 확인되지 않으면 임의로 재계산하지 않는다.
- 종목코드·종목명이 현재 스냅샷과 일치하는 공개 필드만 내보내며 실제 자료는 가상 테스트 화면에 넣지 않는다. 출처 URL·관측 시각·미확인 기준을 함께 보존한다.
- 네이버 일별 가격 응답도 확인했지만 수정주가·확정 상태·거래일 캘린더가 명시되지 않아 RS/이동평균 입력에는 연결하지 않았다.
- 이는 공개 페이지가 사용하는 API이며 안정성이 보장된 계약형 API는 아니다. 응답 변경·접속 실패는 연결 실패로 표시하고 기존 캐시를 가상 성공값으로 바꾸지 않는다. 원천 홈페이지의 재배포 제한을 고려하여 캐시는 개인 로컬 출력에만 둔다.

확인 출처: [삼성전자 공개 화면](https://stock.naver.com/domestic/stock/005930/price), [공개 상세 응답](https://stock.naver.com/api/domestic/detail/005930/detail?codeType=KRX). 외부 데이터 전체를 미러링하거나 계정·보유정보를 조회하지 않았다.

## PER/PBR 입력 연결

현재 저장된 Infomax XLSX 5개에는 PER/PBR/EPS/BPS 항목이 없다. 검토한 관측값 JSON을 준비하면 다음 도구로 새 스냅샷에 연결할 수 있다. 기존 파일은 덮어쓰지 않는다.

```powershell
.\.venv\Scripts\python.exe tools/infomax_valuation.py --base <기존스냅샷.json> --observations <검토된평가관측.json> --output <새스냅샷.json>
```

입력 계약 예시는 도구의 `--help`에 있다. EPS/BPS 단위는 보통주 1주당 원, PER/PBR은 배수다. PER은 TTM, BPS/PBR은 보고일 시점 값이다. `observed_on`은 실제 관측일이며 과거 공시 시점으로 임의 변경하면 안 된다. 생성 결과는 기존 SavedSnapshotProvider에서 읽을 수 있다. PC 로컬 경로·설정은 자동 변경하지 않았다.
