# 재무정보 갱신 기준 · 2026-10-02

사용자 결정: 분기 재무제표 갱신을 기본으로 하고 일간으로 변경을 모니터링한다. 분기 사이 재무수치 변동은 7% 미만이면 다음 정기 갱신으로 이월하고 7% 이상이면 반영한다. 경계가 겹치는 표현은 정확히 7%를 갱신 대상으로 해석했다.

- 최초 확보 및 새로운 분기/반기/사업보고서 기간은 변동률과 관계없이 검증 후 반영한다. 분기말 날짜만으로 갱신하지 않고 실제 제출된 보고서를 확인한다.
- 분기 사이에는 동일 기업·연결/별도·기간·단위·출처의 수치를 마지막 화면 반영본과 비교한다. 일간 확인은 기존 사용자 선택에 따라 앱을 열 때와 열어둔 동안 실행하는 방향이며 닫힌 앱의 OS 예약 실행은 등록하지 않는다.
- 변화율은 `abs(신규값 - 마지막 반영값) / abs(마지막 반영값)`이다. 증가·감소 양쪽에 적용하며 재무제표 금액 항목 중 하나라도 7% 이상이면 검증한 기업 재무 묶음을 반영한다. 단위와 누적/단일 분기는 동일해야 한다.
- 7% 미만은 관측본으로 별도 저장하고 화면 반영본은 유지한다. 후속 비교도 마지막 반영본 기준이므로 작은 변화가 누적해 7%에 도달하면 반영한다.
- 기존 0에서 다른 값으로 변경되거나 부호가 바뀌면 즉시 반영 대상이다. 계정 누락·식별 실패·비교 불가능한 공급자 교체는 검토 대기이며 0이나 성공으로 대체하지 않는다.
- 공개 가격, 시가총액 및 주가로 달라지는 PER/PBR은 이 재무제표 금액 갱신 기준과 별개다. 인포맥스 우선 및 공식 재무와 1억 미만 오차 허용 정책은 유지한다.

구현: 연결 앱의 최초 열기와 열린 화면의 상태 확인이 KST 날짜별 공시 모니터를 시작한다. 닫혀 있던 날짜도 마지막 성공 확인일부터 다시 읽고, 일간 목록의 모든 페이지/건수를 대조한다. 정정·첨부 추가 공시는 원 접수일을 유지하면서 해당 보고기간을 다시 조회한다. 최초 자료는 국내 저장 후보 전체에 대해 순차 수집하며 신규·수정 공시 기업과 직접 선택한 기업을 우선한다. 실패 기업은 다음 일간 확인에서 다시 시도하고 목록 전체 실패는 1시간 뒤 재시도한다. 같은 날 정상 확인은 저장 상태로 중복 방지한다. 자료를 새로 받는 기능은 연결 앱에서 동작하며 단독 HTML에는 수집 기능이 없다.

검증된 보고서만 저장하며 미확보 기간/계정은 추정하지 않는다. 연결재무가 없거나 특수 결산기간·항목명이 확인되지 않은 기업은 검증 대기를 유지한다. 총차입금처럼 주석의 계정 범위가 필요한 항목은 재무상태표의 차입금 몇 개만 합해 임의 총액으로 표시하지 않는다. 기존 인포맥스 자료의 동일 기간 값은 사용자 결정에 따라 우선하고, 이후 새 기간은 DART로 보완한다. 인포맥스 신규 기업·새 수치 자동 조회가 연결된 것은 아니다.

자동 확인 상태에는 반영, 7% 미만/미변경, 일부 기간 대기, 미확보 건수를 표시한다. 자료 반영 후 현재 메뉴/기업과 미반영 보유 입력을 보존하는 기존 새로고침 경로를 사용한다. 수집은 프로세스 잠금과 원자적 파일 교체로 보호하며 서버 종료 시 운영체제가 잠금을 해제한다. 개인 원격 보유 동기화와 독립이다.

최초 전체 수집 중에는 다른 기업의 저장 때마다 화면을 다시 열지 않는다. 현재 분석 기업의 자료가 바뀌거나 전체 확인이 끝났을 때 화면을 갱신한다. 재무 확인일은 완료 종가 기준일과 별도로 관리하므로 기존 검토 가격일이 오래돼도 새 분기 보고서 연결을 막지 않는다. 기존 가격의 날짜를 새 재무 확인일로 바꾸지는 않는다.
