# Goose 적용 가능성 점검

점검일: 2026-10-16 · 환경: company Primary/work · Goose 0.1.0

## 결론과 범위

전부 적용한 상태는 아니다. 기존 대시보드에 같은 목적의 데이터 검증·비교·보고서 열람 기능이 있으며, Goose의 구조화 근거·검토 기록·워크플로 전체가 연동된 것은 아니다. 기존 기능을 Goose 도입의 결과로 소급해 표현하지 않는다.

이번 작업은 설치 패키지와 실제 구현을 대조한 감사다. 기업 조사, 투자 의견 생성, 앱 코드 변경, 서버 재시작, 외부 API 호출, 예약 등록, commit/push는 하지 않았다. 아래 추가 적용 항목도 아직 구현하지 않았다. 사용자의 제외 5개를 우선한다.

## 1. 이미 적용 — 목적이 겹치는 기존 기능

| 항목 | 현재 구현과 적용 범위 | 남은 차이 |
|---|---|---|
| 출처·회계 기준·단위·기준일 확인 | `investment/verification.py`, `src/company_detail_engine.js`: 연결/별도·기간·통화 확인, 연속 분기 TTM, 분모/결측 처리 | 외부 HTML의 모든 숫자와 원문을 자동 대조하는 기능은 아님 |
| 수치 중심 실적 읽기 | `reading()`의 매출 전년 동기 증감·영업이익률 변화·현금흐름/차입금과 기존 추이·가치평가 화면 | 사업 동력·순이익 원인·일회성 판단을 생성하지 않음 |
| 기업 비교·가격 위치 | 기존 비교/동종업계·가격 추세·밸류에이션 기능 | Goose peer-compare 전체 조사 절차를 실행한 것은 아님; 표본·기간·자료 부족을 유지 |
| 최근 뉴스·공시 구분 | `investment/company_events.py`: 제목·출처·발행시각·링크, 각20건, 10분 캐시·실패 시 보존 | 기사 본문 독해·경제적 영향 해석 없음. 네이버 목록 수신은 원문 직접 열람과 다름 |
| 기업별 외부 HTML 등록·열람 | `investment/company_reports.py`, `src/company_reports_ui.js`: 기업 식별·날짜·출처 수동 등록, 원본 해시·중복 방지·다른 버전 보존·정적 열람 | Goose 내부 JSON·출처 장부·작성자 검토 기록의 자동 등록은 없음 |
| 보유·현금·가격 누락 및 집중도 처리 | 기존 포트폴리오 계산/표시 | Goose 다중 통화·환율·목표비중 전체 계산기를 채택한 것은 아님 |
| 연구 출처·리비전·검토 단계 | 기존 research_library/catalog/agents 구조 | 외부 보고서와 주장별 근거 장부는 아직 분리. 모델 공급자 호출은 비활성 |

일부 기업의 상세 분기가 부족하면 해당 읽기/계산은 계속 비어 있을 수 있다. 기능 구현과 전 기업 데이터 확보는 다른 상태다.

## 2. 추가 적용 가능 — 제외 5개를 침범하지 않는 범위

| 우선순위 | 제안 | 적용 경계 |
|---|---|---|
| P1 | Goose HTML에 내장된 report-input.json/source-ledger.json 등을 제한적으로 읽어 제목·종목·작성일·출처 입력을 미리 채우기 | 허용된 JSON만 크기·스키마 검증. 스크립트 실행 금지. 선택 기업과 보고서 종목 불일치 시 등록 보류. 일반 HTML 수동 등록 유지 |
| P1 | 등록 상태와 검토 상태를 분리하고 출처 접근 범위를 표시 | 등록됨/검토 기록 없음/작성자 검토 기록 첨부 등을 구분. direct_read/prior_record/blocked/not_published와 접근일·발행일 구분. 작성자의 verified 선언을 우리 검증 완료로 바꾸지 않음 |
| P2 | 출처 목록과 근거 파일을 iframe 밖에서 열람·다운로드 | 현재 원문 URL은 수동 입력분만 밖에서 열 수 있음. 내장 근거 파일은 별도 추출·검증 후 제공. HTML 안 외부 실행 차단 유지 |
| P2 | 보고서와 저장 자료의 기준일·수치를 나란히 비교 | 재무기간·연결/별도·통화·단위·지표 정의가 같을 때만 차이 산출. 수치 덮어쓰기·출처 우선순위 변경·자동 투자 의견 반영 없음 |
| P2 | 이전 보고서를 기준으로 날짜·출처·수치의 변경 목록 제공 | 기존 버전은 보존. 기계적 차이만 표시하고 판단 변경 조건이나 시나리오를 생성하지 않음 |
| P3 | 주장별 근거 연결과 사실/전망/추론 표시 | 보고서에 작성된 분류를 표시하는 기능. 자동 사실 판정이나 제외한 분석 내용의 신규 생성으로 확장하지 않음 |
| P3 | 차트와 표의 수치·단위·기간·출처 접근 개선 | 단순 관측 정보를 보완. 대시보드에 장문 목차·브랜드·의견 분량 요건을 강제하지 않음 |

권장 순서는 P1 입력 보조·상태 구분 → P2 근거 열람·자료 대조 → 기계적 버전 비교다. 별도 포트폴리오 계산기를 중복 도입하기보다는 필요한 누락·환율 표기만 기존 엔진에 검토한다.

## 3. 제외 — 사용자 결정 유지

1. 사업구조/제품별 성장 동력 분석 생성.
2. 순이익 증가 원인 및 일회성 이익 구분 생성.
3. 최신 뉴스가 매출·비용·현금에 미치는 영향 분석 생성.
4. 성장/기준/악화 시나리오 및 판단 변경 조건 생성.
5. 모든 기업을 같은 깊이로 자동 분석·갱신.

따라서 stock-report의 deep_report 전체 요건과 earnings-review/event-impact/watchlist-review의 해당 해석 절차를 그대로 자동 실행하지 않는다. deep_report의 장문 분석·의견 분량 요건을 일반 등록의 필수 조건으로 삼지 않는다. 짧은 비교/팩트체크 등 다른 문서 형식은 별도 범위로 활용할 수 있다.

사용자가 직접 만든 외부 보고서에 위 내용이 포함돼 있어도 등록·열람만으로 그 내용을 우리 시스템이 생성하거나 판단에 자동 반영할 권한이 생기지 않는다. 기존 가치평가 계산식의 민감도와 새 서사형 시나리오 생성도 구분한다.

## 4. 환경상 제한 — 불가능과 미연동을 구분

| 항목 | 확인 결과 |
|---|---|
| 자동 조사/에이전트 실행 | workflow-map.json은 declarative_agent_workflow이며 host_api=false. 설치만으로 실행 API가 생기지 않는다. 대화 환경의 조사 도구와 앱의 자동 실행기는 별개다 |
| 모델 API | `investment/agent_providers.py:10` API_ENABLED=False. 유료 모델 자동 호출은 현재 정책상 비활성. 스킬 설치로 바뀌지 않음 |
| 실제 원문 확인 | 렌더러/감사 스크립트가 인터넷 원문을 대신 읽거나 모든 계산을 재검산하지 않는다. URL·장부·hash·형식 통과만으로 사실 검증 완료라고 할 수 없음 |
| 웹 수집 지속성 | 공개 사이트 응답·접근 차단·원문 공개 여부에 좌우됨. 실패/미열람을 표시해야 하며 스킬로 권한이 추가되지 않음 |
| HTML 정적 열람 | 현재 iframe/CSP에서 스크립트·외부 리소스·내장 JSON 다운로드·본문 외부 링크 제한. Goose 기본 차트는 정적 인라인 SVG라 표시 가능한 구조. 다른 동적 HTML은 차트가 생략될 수 있음 |
| 파일 크기 | 현재 UTF-8 단일 HTML 3MB 이하. Goose는 PNG와 여러 JSON을 base64로 내장하므로 내용에 따라 한도를 넘을 수 있음; 모든 Goose 보고서가 등록 가능하다고 단정하지 않음 |
| PC 간 보고서 공유 | 외부 보고서 SQLite는 현재 PC 로컬 보관, Git/기존 보유자료 동기화 대상 아님. 스킬 설치와 별개 |
| 예약/시장 마감 브리핑 | Goose scheduling 문서는 실행 환경의 별도 예약 기능을 요구. 현재 신규 예약 없음. 예시 16:10을 기존 시장 갱신 시간 정책으로 대체하지 않음 |

## 호환성에서 바로잡을 점

Goose 기본 render_report.py는 인라인 SVG 차트를 생성한다. 따라서 기본 차트를 모두 동적 차트로 보고 표시 불가라 설명하면 부정확하다. 다만 기본 보고서의 외부 글꼴은 차단돼 대체 글꼴로 보일 수 있으며, 내장 JSON 다운로드와 출처 링크는 현재 정적 뷰어에서 그대로 동작하지 않는다. 원본 HTML은 변경 없이 별도 보존한다.

Goose의 최종 납품 감사는 구조·검색/검토 기록·입력/미리보기 해시를 확인하는 절차다. 서명된 외부 인증이나 원문 진실성의 자동 증명은 아니다. 제외 범위를 포함하는 심층 보고서 감사 요건을 우리 일반 등록의 강제 관문으로 복사하면 안 된다.

이번 점검만으로 운영 서버의 최신 반영 상태나 원격 main 최신성을 확정하지 않는다. 점검 기준은 회사 바탕화면 원본 main의 미커밋 구현이며 옛 investment-up 워크트리 코드와 구분했다.


## 점검 이후 구현 업데이트 · 2026-10-16

사용자 후속 요청으로 내장 출처·작성자 검토 상태 표시를 추가했다. 기존 등록분에도 적용하며 SK하이닉스는 작성자 limited/중복 제외 원문32개로 확인했다. 위 본문의 미적용 평가는 최초 감사 시점 기준이다. 현재도 제목/날짜 자동 채우기, 근거 파일 다운로드, 보고서-저장 재무 수치 대조, 버전 비교는 미구현이다. 새 기능의 운영 반영 상태는 CURRENT_HANDOFF.md를 따른다.


### 후속: 폴더 자동 등록

사용자 요청에 따라 지정 폴더의 Goose HTML에서 종목코드·기업명·as_of를 확인해 자동 등록하는 기능을 추가했다. UI에서 매번 제목·날짜·파일을 입력할 필요가 없다. 직접 업로드 폼의 입력 자동 채우기, 근거 파일 다운로드, 수치 대조, 버전 비교는 별도다. 기업 조사·보고서 생성 및 제외5개는 계속 자동 실행하지 않는다. 사용법은 EXTERNAL_REPORTS.md 참조.
