# 재무자료 수집 경로 점검 · 2026-10-02

## 판단

현재 구현에서 기업 범위 확장은 DART 공개 연결재무제표를 조회·검증·저장하는 경로가 먼저 실행 가능하다. 인포맥스는 저장 파일을 읽는 연결이며 신규 기업 자동 수집은 연결되지 않았다. 따라서 두 공급자의 신규 기업 조회 속도 중 승자를 단정할 수 없다. 인포맥스 자료가 있는 기업은 기존 우선순위를 유지하고, 없는 기업은 DART로 보완한다. 화면은 저장 자료를 재사용하고 재무자료는 공시 갱신 때 교체하는 방식이 적합하다.

## 실제 측정

회사 PC의 동일 실행 환경에서 관측한 소량 표본이며 공급자 성능 보장이 아니다.

| 경로 | 측정 범위 | 관측 | 결과 |
|---|---|---|---|
| 기존 저장자료 | 3개 기업 인포맥스 Excel 및 공식 보완자료 읽기, 3회 | 0.230 / 0.034 / 0.041초 | 읽기 성공. 신규 기업 다운로드 시간 제외 |
| DART 삼성물산 | 기업 식별 → 2026 반기 CFS 목록 → 원문 → 검증 → 로컬 저장, 1회 | 0.232초 | 저장 성공. 분기 이력 전체나 화면 반영까지의 시간은 아님 |
| DART 효성중공업 | 동일 반기 조회 및 검증 시도, 1회 | 0.079초 | 주요 손익 계정 미확인으로 중단. 성공 저장 시간으로 사용하지 않음 |
| DART 효성중공업 | 이미 식별한 원문 1건 다운로드만, 3회 | 0.120 / 0.027 / 0.045초 | 원문 수신. 식별·검증·저장 제외 |
| 인포맥스 신규 기업 | 공급자에서 새 기업의 재무자료 조회·저장 | 미측정 | 현재 저장 파일 어댑터만 있으며 자동 신규 수집 미연결 |

효성중공업 원문에는 총 순이익 행 이름이 `분기`로만 표시되어 기존 계정명 검증을 통과하지 않았다. 다운로드 지연과 계정 해석 실패를 구분해야 한다. 값 추정이나 빈칸의 0 대체는 하지 않는다. 실제 측정 원문·결과는 Git 제외 validation 폴더에 저장했다.

## 안정적인 확장

OpenDART 단일회사 전체 재무제표 API는 JSON/XML, 연결(CFS)/별도(OFS), 표준 계정 ID와 당기/누적 금액을 제공한다. HTML 항목명만 해석하는 방식보다 계정 식별에 유리하지만 비표준 계정 및 분기·누적 검증은 여전히 필요하다. 인증키가 필수이며 이번 실행 환경의 OPENDART_API_KEY는 설정되지 않았다. API 호출 속도는 측정하지 않았다.

공식 문서: https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020

인포맥스 전체 기업 재무 일괄 추출이 실제 연결되면 동일 기업·동일 기간·동일 계정·최초 조회/재조회 조건으로 다시 측정해야 한다. 현재 저장자료 읽기 시간을 인포맥스 신규 수집 속도라고 제시하지 않는다.

## 진행 상태

위 속도 점검 당시에는 후보 수집/화면 연결이 미완료였다. 이후 사용자 요청으로 분기 정기·일간 7% 재무 갱신을 연결했다. 삼성물산·효성중공업 각각6개 연결보고서의 실제 저장과 화면 금액/기간 검사를 통과했다. 상세 운영 기준과 확보 범위는 FINANCIAL_UPDATE_POLICY.md 및 PROJECT_STATE.md를 따른다. 인포맥스 신규 수집/API 속도가 새로 측정된 것은 아니다.
