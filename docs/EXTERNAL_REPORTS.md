# 종목별 외부 보고서

기업 분석의 간단 분석 화면에서 기업을 선택한 다음, 뉴스 목록 위의 **외부 분석 보고서 → HTML 보고서 등록**을 펼친다.

1. 보고서 제목·작성일·출처/작성도구를 입력한다. 예: Goose. 원문 출처 URL은 선택 사항이며 줄마다 하나씩 최대20개 등록한다.
2. UTF-8 HTML(.html/.htm) 파일을 선택하고 **선택 기업에 등록**한다. 파일은3MB 이하이며 미래 작성일은 등록할 수 없다.
3. 등록한 제목을 누르면 별도 읽기 전용 창에서 내용과 출처를 확인한다. 기업별 최신 작성일순 최대50개 목록을 보여준다.

작성일은 보고서 작성일이며 재무기간/가격일을 대체하지 않는다. 등록 자료가 우리 재무·가격 계산 또는 투자 판단에 자동 반영되지 않는다. 동일 기업·내용·메타데이터의 중복 등록은 기존 자료를 반환하며, 다른 자료를 덮어쓰지 않는다.

보고서 원본은 현재 PC 설정 data_dir/profile/user_input/external-reports.sqlite3에 보존한다. Git 및 개인 보유자료 동기화에 포함하지 않는다. 다른 PC의 등록은 별도이며 외부 서비스로 업로드하지 않는다. 실제 Goose 보고서 설치·생성·자동 연결은 이 기능에 포함되지 않는다.

열람은 iframe sandbox 및 콘텐츠 제한을 적용한 정적 HTML 사본이다. 글/표/인라인 SVG/인라인 스타일과 일부 내장 이미지를 표시한다. 스크립트·폼·외부 글꼴/이미지·외부 연결은 차단되어 동적 차트가 생략될 수 있다. 원본 자체는 수정하지 않고 해시로 확인한다. 원문 출처 URL은 읽기 창 위에서 별도로 연다. 여러 파일/외부 assets가 필요한 보고서는 단일 UTF-8 HTML로 준비한다.

등록과 열람은 로컬 운영 서버의 인증 경로를 사용한다. 읽기 전용 서버는 등록을 거부한다. 코드 변경 뒤에는 기존 열린 탭 입력을 보관하고 안전 재시작한 후 사용한다.

## 내장 출처와 검토 상태

Goose 보고서에 report-input.json/source-ledger.json이 내장돼 있으면 기존 등록분도 원본을 읽어 출처와 작성자의 검토 상태를 표시한다. 다시 등록할 필요가 없다. 목록에는 `작성자 표기: 초안 / 조사 한계 있음 / 검증본`, 해당 정보가 없는 일반 HTML에는 `검토 상태 미기재`를 표시한다. 작성자의 상태나 감사 통과 선언은 우리 시스템의 사실 검증 결과가 아니다.

읽기 창 위의 **원문 출처 · N개**를 펼치면 내장 출처의 제목·발행처·발행시각과 직접 입력한 출처를 볼 수 있다. 공개 HTTPS 주소만 새 탭으로 연다. 같은 URL은 중복 표시하지 않는다. 종목/내장 기준일이 서로 다르거나 자료 형식·주소가 부적절하면 보류 또는 제외 안내를 표시한다. JSON 추출은 스크립트를 실행하지 않으며 보고서 원본·DB·재무 계산을 바꾸지 않는다. 원문을 자동 방문하지 않는다.


## Goose 폴더 자동 등록

기본 폴더는 현재 PC의 `다운로드/Goose Reports`다. 로컬 운영 서버를 켜면 폴더를 만들고 약5초마다 확인한다. Goose HTML을 이 폴더에 저장하면 저장이 안정된 것을 확인한 뒤 보고서에 내장된 종목코드·기업명·작성 기준일(as_of)로 해당 기업에 등록한다. 파일명을 바꿔도 종목 연결은 내장 정보로 결정한다. 신규 작성이나 분석·조사는 실행하지 않는다.

기업분석 **간단 분석 → 외부 분석 보고서 → 폴더 자동 등록**에서 이 PC의 실제 경로를 확인·복사하고 파일별 상태를 볼 수 있다. 표시 목록은 약15초마다 갱신하며 `폴더 다시 확인`으로 바로 확인할 수도 있다. 서버를 꺼 둔 동안 저장한 파일은 다음 실행 때 처리한다. OS 예약·로그인 자동 실행은 추가하지 않는다.

- 단일 UTF-8 .html/.htm, 3MB 이하. 하위 폴더와 다운로드 임시 확장자는 확인하지 않는다.
- 내장 report-input.json과 저장된 기업 목록의 코드·기업명이 일치해야 한다. 내장 출처 장부가 있으면 코드·기준일도 일치해야 한다. 인식되지 않는 일반 HTML은 기존 수동 등록을 사용한다.
- 같은 기업의 같은 HTML 내용은 수동 등록분까지 포함해 중복을 막는다. 다른 내용은 새 버전으로 보존한다.
- 원본 파일은 이동·삭제·수정하지 않는다. 오류/미확인은 상태를 표시하고 파일을 보존한다. 파일이 다시 저장되면 재확인한다. 파일/DB의 일시적 접근 실패는 재시도한다.
- 폴더당 최대500개, 한 차례 최대20개 처리. 처리된 파일은 필요에 따라 사용자가 별도 보관할 수 있다. 바로가기 파일은 등록하지 않는다.
- 읽기 전용 서버에서는 감시·폴더 생성·자동 등록을 하지 않는다. 코드가 변경되면 자동 등록을 멈추고 안전 재시작을 기다린다.
- 다른 폴더를 쓰려면 이 PC의 비공개 `config/local.json`에 `goose_report_inbox`를 지정한다. 상대 경로는 프로젝트 루트 기준이다. 이 경로·원본·처리 기록·보고서 DB는 Git/PC 간 자동 공유 대상이 아니다.

재무·가격 계산 및 투자 판단에는 자동 반영하지 않는다. 상태의 `작성자 표기`와 시스템의 사실 검증 결과를 계속 구분한다.
