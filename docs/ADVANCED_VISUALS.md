# EBITDA 입력·계산 변경 · 2026-10-01

위험·금융 시계열 확장(2026-10-07): [계산/출처/검증 계약](PORTFOLIO_RISK.md)을 참조하세요.

- 주요 재무표에서 EBITDA/매출액을 삭제했다. 나머지 11개 지표와 카드/비교 막대를 유지한다.
- EBITDA 셀을 클릭하거나 **EBITDA 입력 · 계산**을 펼쳐 기업·기간·연결/별도를 확인한다. **EBITDA 직접 입력**에 억원 금액을 넣고 **표에 반영**을 누르면 된다. 0과 음수도 입력할 수 있다. 빈칸은 미확보로 처리하며 0으로 바꾸지 않는다.
- **영업이익 + 상각비로 계산**은 영업이익 + 감가상각비 + 무형자산상각비를 합산한다. 표의 영업이익을 미리 채우며 필요하면 수정할 수 있다. 상각비 두 항목은 같은 기간·연결/별도의 값이어야 한다. 감가상각비가 두 상각비의 합계이면 무형상각비에 0을 넣어 중복 합산을 피한다. 누적 상각비를 단독분기 영업이익과 섞지 않는다. 회사 공시값은 직접 입력하고 원문 출처/메모를 남길 수 있다.
- 이 계산기는 **영업이익 기준 계산값**이다. FnGuide의 EBIT/조정영업이익 + 현금흐름표 상각비 정의를 참고한 계산이며, 회사 공시나 다른 제공자의 EBITDA 정의와 다를 수 있다. 미국 SEC의 EBITDA 정의는 당기순이익에서 이자·세금·상각 영향을 제외하며 영업이익과 동일하지 않음을 설명한다. 원천 정의를 확인해 직접 입력 또는 계산을 선택한다. [FnGuide 산식](https://wcomp.fnguide.com/Help/Guide?cmp_cd=466690), [SEC EBIT/EBITDA 설명 103.01·103.02](https://www.sec.gov/rules-regulations/staff-guidance/corporation-finance-interpretations/non-gaap-financial-measures).
- 입력값은 표에 *와 사용자 직접 입력/계산 및 메모로 표시한다. EBITDA/이자비용은 같은 표시 기간 이자비용이 양수일 때 갱신한다. 총차입금/EBITDA는 같은 기간의 연간 EBITDA가 양수일 때만 갱신한다. 현재 실제 분기 표에서는 연간 비율을 계산하지 않는다.
- 반영한 입력값은 이 브라우저의 저장소에 보관하고 재접속·새로고침 때 복원한다. 실제/가상 모드, 종목 코드·명칭·시장, 회계기준, 기간 종류와 날짜를 확인한다. 브라우저 저장이 차단되면 파일 저장 안내를 표시한다. **입력값 파일 저장**은 모든 기업·기간의 입력값과 계산 내역을 억원 단위 JSON으로 저장한다. 다른 PC에서 최신 대시보드의 **입력값 불러오기**로 복원한다. 해당 파일의 입력 목록으로 교체하며, 기업·기간이 현재 표와 다른 항목은 제외한다. 잘못된 모드·단위·중복·계산 불일치는 기존 입력을 보존하고 거부한다.
- **이 기간 수기값 지우기**는 선택한 기간의 입력만 제거하고 원래 저장자료 표시로 돌아간다. 개인 입력값·파일·메모는 원자료/운영 DB/Git에 자동 반영되지 않는다. 서버 갱신·포트폴리오/조건검색 엔진에도 수기 EBITDA를 자동 주입하지 않는다.
- 상각비 원자료는 현재 회사 PC에 연결되어 있지 않다. 입력 전 EBITDA 결측은 계속 —다. 실제 HTML UI 검증에서 사용한 금액은 명시적 가상 입력이고 캡처 전 모두 제거했다.

# 기업 간단 분석 · 주요 재무지표 · 2026-10-01

**기업 간단 분석**에서 종목을 선택하면 주요 재무지표가 표시된다. 상단에는 최신 매출액·영업이익·당기순이익·총차입금 카드가 있고, 아래에는 첨부 예시 형태의 기간별 표와 매출액/영업이익 비교 막대가 있다. 연결/별도 및 연간/단독분기/누적은 분리한다. 여러 기간 종류가 있으면 표시 기간을 선택할 수 있다. 모바일에서는 표를 좌우로 움직여 보며 항목명은 고정된다.

금액은 억원, 비율은 % 또는 배다. 금액은 정수, 비율은 소수 첫째 자리로 표시하며 각 셀에 원값·출처를 제공한다. 손익은 해당 표시 기간의 실적이고 차입금은 기말 잔액이다. 막대마다 같은 0 기준을 사용하며 음수도 보존한다. 결측은 —, 산출 범위 확인이 필요한 값은 *로 표시한다.

현재 회사 PC 자료는 삼성전자·SK하이닉스·현대차의 2025.09/12·2026.03/06 연결 단독분기 4개다. 실제 연간 실적·EBITDA가 없으므로 해당 값은 비워 둔다. 총차입금/EBITDA는 연간 자료에만 계산한다. 기존 총차입금 검토값은 혼합 출처 추정치 및 계정 범위 불확실성을 카드와 표에 표시한다. 과거 총차입금까지 자동 추정하지 않는다. 상세 이력이 없는 후보에는 기간 미확인 참고 비율만 표시하고, 기간별 비교는 자료 연결 대기로 안내한다.

기존 `config/local.json`의 `manual_snapshot_file` 부모 폴더를 사용한다. `config-review.json`, `info.xlsx`, `income.xlsx`, `balance.xlsx`가 필요하고 `income-extra.xlsx`, `debt-extra.xlsx`는 선택 사항이다. 현재 읽기 계약은 user_input / CFS / 손익 순 / 재무상태 누적 / 인포맥스 기존 천원 단위다. 종목 식별·날짜·중복·회계기준·금액 대조가 맞는 자료만 연결한다. 기존 원자료와 DB를 쓰거나 새로 수집하지 않는다. `export_workspace`, Streamlit HTML 내보내기, 기존 갱신 화면에 공통 연결했다.

출처/산출 범위 펼치기에서 기간별 출처·공개일과 혼합 출처 설명을 확인할 수 있다. 저장 재무의 공개일이 미확인이면 과거 시점 검증용으로 사용할 수 없다는 안내를 유지한다. K-IFRS 표준 여부를 원천에서 확인하지 못해 임의로 붙이지 않고 CFS/OFS를 표시한다.

검증: `tests/test_financial_table.py`는 단위·분모·음수/0·기간·기준 분리·미래/중복·식별·로컬 입력 검사를 수행한다. `tests/test_financial_table_ui.py`는 가상 UI와 선택적 `FINANCIAL_ACTUAL_HTML`의 실제 저장 HTML을 검사한다. 이때 새 API 조회나 운영 DB 쓰기는 없다. 실제 파일과 캡처는 Git 공유에서 제외한다.

# 사용 전 전체 점검 · 2026-10-01

- 기존 상세·조건검색·비교 메뉴에는 검토 자료임을 표시해 전체 기업 발굴과 구별한다. 화면과 기존 엔진은 보존한다.
- 기업 발굴의 관심목록과 검색 조건을 같은 탭의 새로고침 후 복원한다. 실제/가상 모드는 별도 보관하며 종목명·시장·코드가 바뀐 관심 항목은 제외한다. 탭을 닫기 전에는 관심목록 JSON으로 저장한다. 브라우저 저장소가 차단되면 파일 저장 안내를 표시한다.
- 공개 후보를 선택해도 전체 보유·포트폴리오 메뉴로 이동할 수 있다. 해당 후보의 검토되지 않은 기업 상세는 계속 차단한다.
- Advanced 필터 적용 후 선택 종목이 결과에서 빠지면 첫 결과를 선택한다. 결과 0개이면 빈 패널을 표시한다.
- ROE×PER 분포는 양수 PER만 집계한다. 미확보와 PER 0 이하를 따로 표시하고 전체 합계에 포함한다. ROE 0은 유효값이다.
- 업종 PER/PBR 중앙값은 양수 값과 동일한 재무기간·회계기준·가격일을 요구한다. 가격 RS·지수 초과수익의 출처·기간을 화면과 CSV에서 함께 표시한다. 가격 패널에 관측일·기간·단위·원천 조정 한계를 표시한다.
- 새 회귀 검사: `tests/test_workspace_audit_ui.py`. 관심목록 저장/불러오기·새로고침·식별 변경, 공개 후보 이후 메뉴 이동, 필터 선택·빈 결과·리셋·모바일을 검증한다.
- 전체 Python 288개, JS 4개 묶음, 브라우저 6개 묶음, 실제 2,455개와 독립 HTML 18개 메뉴·전체 CSV·390px 검증을 수행했다. 실제 보유 입력은 0개이며 보유 엔진 대조는 가상 입력을 사용했다.

# Advanced Visuals · 2026-09-30

## 회사 PC 실데이터 확인 · 2026-10-01

회사 PC에서 원격 a600892를 수신한 뒤 실제 공개 캐시로 새 탭을 검증했다. 후보 2,455개·가격 이력 2,454개·RS 2,290개이며 기존 검토 상세는 3개로 분리한다. 시장 가격은 2026-09-29, 기존 인포맥스 상세 가격은 2026-09-23이다. 아래의 실제 캐시 부재·상대 PC 검증 대기는 구현 당시 작업본의 기록이다.

회사 PC의 로컬 결과는 `validation/advanced_actual_20261001.html`이다. 이 파일을 브라우저로 열고 **Advanced Visuals** 메뉴를 선택한다. 기존 exporter/live_dashboard도 같은 새 탭을 포함한다. 저장 HTML과 공개 캐시·DB·보유 입력은 Git 전송 대상이 아니다.

실제 자료에서 검색·선택·필터·복원·삼성전자 가격/출처·전체 집계·unknown/unavailable·390px·JS 오류 0을 확인했다. 보유 판단·비중·손익·최대 5종목 구성안·현금은 테스트 브라우저의 명시적 가상 입력으로 기존 엔진 결과와 대조했다. 현재 실제 보유 입력 0종목을 가상 성공으로 대체하지 않는다.

로컬 HTTP 미리보기 실행은 자동 승인 검토에서 별도 지속적 서비스 승인이 없다는 이유로 거부돼 서버가 실행되지 않았다. 로컬 HTML 파일과 검증용 브라우저 메모리 응답으로 확인했다. 생성 파일은 약 55MB이므로 화면 집계 시간과 파일 로드 시간을 구분한다.


기존 통합 HTML의 메뉴에서 Advanced Visuals를 선택한다. workspace_export/live_dashboard가 공급하는 discovery.snapshot + discovery.research를 사용하며, 분석 상세와 보유 엔진에는 원래 analysis_snapshot 및 iframe의 검토 입력만 유지한다. 새 의존성은 없다.

전체 후보를 샘플링 없이 ROE × PER 10×10 셀에 집계하고, 결측을 따로 센다. 끝 셀은 범위 밖 수치를 포함한다. 결과 수 / 원본 모집단 / 표시 수를 표시하고 종목 목록은 페이지당 25개다. 시장·업종·ROE·PER/PBR·가격 RS·52주 하락폭·가격 추세 필터는 DiscoveryEngine.filter를 재사용한다. RS 순위를 필터 모집단으로 다시 계산하지 않는다.

선택 기업은 기존 technical.series와 지표별 metric_details, 저장된 events만 표시한다. 뉴스 부재는 이벤트 위험 없음이 아니다. 공개 참고 수치와 검토 상세 연결을 구분하고 기간·CFS/OFS 미확인은 unknown으로 유지한다. 기존 간단 분석 버튼에서 원래 보완자료/원문 연결로 이동한다.

보유 화면은 iframe의 INVESTMENT_GET_HOLDINGS / INVESTMENT_GET_POLICY를 읽고 PortfolioEngine.reviewHoldings / propose의 결과를 표시한다. 비중·손익·판단 근거와 최대 5종목 구성안은 기존 엔진 결과다. 공분산 위험 기여도는 자료 미연결로 unknown이다. 매크로 맵은 관계 탐색 구조만 제공하며 연결 강도는 unavailable이다.

필터와 선택 코드만 sessionStorage에 저장한다. 보유·인증정보를 추가 저장하거나 서버에 보내지 않는다. 새로고침 후 탭·필터·선택을 복원한다. 보유 자체의 일반 새로고침 복원 정책은 기존 화면을 따른다.

검증: node tests/test_advanced_visuals.js, Python tests/test_advanced_visuals_ui.py. ADVANCED_SCALE_FIXTURE=1이면 2,455개 별도 가상 발굴 후보를 주입하며 기존 상세 8개와 분리한다. ADVANCED_ACTUAL_HTML은 실제 기존 내보내기 HTML 경로를 명시하면 읽기 전용으로 그 자료를 검증한다. 실자료를 Git에 포함하지 않는다.

이 PC에는 실제 2,455개 공개 캐시가 없다. 회사 PC에서 main 수신 후 기존 저장자료로 내보내기/서버를 다시 열고 실제 2,455개·일봉 2,454개·RS 2,290개 및 출처를 확인해야 실데이터 완료 기준을 충족한다. 이 수치를 상수로 화면에 만들어 넣지 않았다. 전체 데이터 및 포트폴리오 엔진 결과의 부족은 unknown/unavailable로 보존한다.

## 검토 상세분석

로그인 후 스탁이지의 6개 탭 구성을 참고한 새 검토 상세분석은 [COMPANY_DETAIL.md](COMPANY_DETAIL.md)를 참고한다. 상세분석과 기업 간단 분석은 동일한 관심목록·EBITDA 입력 도구를 사용한다. 고급 시각화와 보유·포트폴리오 화면은 기존 엔진을 유지한다.
