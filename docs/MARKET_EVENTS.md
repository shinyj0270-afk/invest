# 공시·뉴스 반영 (4단계)

## 사용

대시보드 실제 저장자료 → 기업 상세 → **공시·뉴스 · 출처 확인과 재검토**에서 `공시·뉴스 새로고침`을 누른다. 보유·연구 입력은 화면 재실행 전에 JSON으로 내보낸다. 수집 후 다시 가져오면 기존 수량·투자 논리를 유지하면서 현재 이벤트 상태가 연결된다.

CLI는 다음과 같다. 종료 코드 0은 수집 완료 또는 파일 입력 완료, 2는 일부 출처 실패/연결 대기, 1은 실행 오류다.

```powershell
.\.venv\Scripts\python.exe tools\refresh_market_events.py --codes 005930 000660 005380
.\.venv\Scripts\python.exe tools\refresh_market_events.py --codes 005930 --input private_data/events.json
```

기존 `tools/verify_portfolio_data.py`에 `--events-cache`를 추가하면 같은 PC의 현재 공시·뉴스 검토 상태를 연결한다. 옵션을 생략하면 기존처럼 전달받은 보유 파일·시장 스냅샷만 검증한다.

## 출처와 범위

- 삼성전자: [공식 뉴스룸 RSS](https://news.samsung.com/kr/feed)의 현재 제공 목록. 발행 기업 기준으로 005930에 연결한다. 기사별 실제 대상 기업·중요성은 원문을 검토한다. 홍보성 소식도 포함되며 전체 언론이나 장기 뉴스 이력을 포괄하지 않는다.
- DART: [공식 공시검색 API](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001). 설정한 법인의 최근 30일 공시를 기존 Reader로 조회한다. 정정 공시를 제외하지 않으며 반환된 stock_code가 요청 종목과 일치할 때만 연결한다. 법인 고유번호를 종목코드로 추측하지 않는다.
- 다른 뉴스와 조회 기간 밖 공시는 아래 형식으로 수동 입력할 수 있다. 조회 실패를 가상 자료로 대체하지 않는다. 빈 목록은 전체 시장에 이벤트가 없음을 뜻하지 않는다.
- 현재는 수동 새로고침이다. 백그라운드 예약이나 대시보드 시작 시 공시·뉴스 자동 조회는 등록하지 않는다.

## PC별 DART 연결

각 PC의 Git 제외 `config/local.json`에 명시된 profile을 유지하며 enabled_data_adapters에 dart를 추가하고, market_events.dart_corp_codes에 **공식 확인한** 종목코드 → 8자리 DART 법인 고유번호를 등록한다. `config/runtime.local.json`은 같은 profile과 permissions.dart=true가 필요하다. 키는 환경변수 OPENDART_API_KEY로 제공한다. 코드·예제·오류 메시지에 키를 저장하지 않는다. 자동으로 PC 설정이나 권한을 변경하지 않는다.

```json
{"market_events": {"dart_corp_codes": {}}}
```

## 수동 입력 계약

다음은 형식 설명용 가상 예시이며 실데이터 확인 자료가 아니다. 실제 모드에 넣을 때는 실제 확인한 제목·날짜·원문으로 교체한다. 종목코드는 현재 스냅샷에 포함되어야 한다.

```json
{
  "schema_version": "market-events-0.1",
  "data_mode": "user_input",
  "items": [{
    "code": "005930", "kind": "news",
    "title": "형식 설명용 제목", "source": "실제 발행 출처",
    "url": "https://example.invalid/replace-with-source",
    "published_on": "2026-09-29", "published_at": null
  }]
}
```

kind는 news 또는 disclosure다. 날짜는 한국 날짜이며 시간대가 있는 published_at은 선택이다. DART 접수일에 임의의 발표 시각을 붙이지 않는다. 미래 발표일, 잘못된 URL/종목/날짜를 거부한다. 파일에 넣은 reviewed, needs_review, opinion은 채택하지 않는다.

## 저장과 판단

Provider → 정규화 → 기존 PC별 SQLite의 별도 market_event_versions 테이블 → 보유 입력 → 기존 판단 엔진 순서다. 제목·출처·링크·발표일·첫 수집 시각과 사용자의 확인 여부를 저장하며 기사 본문과 인증정보는 저장하지 않는다. 기존 가격 스냅샷과 연구 signals 테이블은 수정하지 않는다.

- 동일 내용은 중복 저장하지 않는다. 같은 링크의 내용 변경은 새 버전으로 보존하고 재검토 대상으로 둔다. 정정 공시는 별도 접수번호 링크를 보존한다.
- 한 출처의 응답 검증 실패 시 그 응답 전체를 거절하고 이전 자료를 유지한다. 다른 출처 성공은 저장하며 결과는 partial로 표시한다. UI는 예외 종류만 보여준다.
- 공시 전체와 제목에 실적·배당·자기주식·정정·유상증자·감자·합병·영업정지·횡령·배임·공급계약·투자·인수가 있는 뉴스를 검토 대상으로 분류한다. 단순 키워드이므로 누락·과잉 분류가 가능하다.
- 미확인 주요 이벤트는 `주요 공시·뉴스 재검토 필요` 사유로 HOLD/신규 편입을 보류한다. 기존 검토에서 확인된 중대한 위험의 SELL 검토 표시는 유지한다. 자동 매수·매도, 감성 점수, 재무 수치 덮어쓰기는 하지 않는다.
- 원문·투자 논리를 검토하고 확인 버튼을 누르면 해당 버전의 이벤트 보류만 해제된다. 기존 가격 기한·연구 근거 등의 조건은 그대로 검사한다. 필요하면 보유 JSON의 투자 논리도 수정한다.
- 표시 페이지는 30건씩, 엔진에 전달하는 미확인 이벤트는 최대 100건이다. 100건보다 많아도 판단 보류가 유지되며 순차 확인할 수 있다.
- 수집·발표일 이후에만 이벤트를 노출한다. 검토 표시는 현재 상태로 저장하므로 과거 시점의 검토 이력 재현이나 백테스트에는 사용하지 않는다.
- 수집 범위 밖 사건, 수집 실패, 키워드 미탐지를 엔진이 발견할 수는 없다. `pending_events=[]`는 수집된 주요 이벤트 중 미확인이 없다는 뜻이다. 전체 공시 검토 완료라는 의미가 아니다.
