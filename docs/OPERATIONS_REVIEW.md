# 운영 방식 정기 점검

사용자 결정(2026-10-19): Orca 기반 현재 작업 방식(원본 main + Orca 작업 워크트리 하나 + 작업 단위 세션 + Claude/Codex/ChatGPT 분담)이 계속 최선인지 정기적으로 점검한다. 예약은 두지 않는다. 매월 첫 INVESTMENT START에서 이번 달 기록이 없으면 AI가 "운영 점검 시기"라고 알리고, 점검은 사용자가 원할 때 진행한다.

## 역할

- 판단·대안 선택: ChatGPT 주도(공통 역할 규칙), 최종 결정은 사용자.
- 수치 수집: 그 시점 START한 Claude/Codex가 Git 로그·CURRENT_HANDOFF·PROJECT_STATE·로컬 검증 기록에서 아래 항목을 읽기 전용으로 정리한다. 추정치는 추정으로 표시한다.
- 점검 결과로 규칙·도구를 바꾸면 기존 MERGE/CLOSE 절차를 따른다. 점검만으로 설정·예약·워크트리를 바꾸지 않는다.

## 점검표

| 항목 | 확인 방법 | 바뀌면 검토할 신호 |
|---|---|---|
| 동시 쓰기 | 인계 기록의 다른 쓰기 세션 감지·보류 횟수, 같은 작업본을 연 세션 수 | 같은 작업본에 두 세션이 동시에 쓴 사례 |
| 반영 부담 | 기능 1건당 MERGE·안전 재시작·입력 보관 확인 횟수 | 재시작 확인이 작업 흐름을 자주 끊음 |
| 사용량·세션 길이 | 세션당 commit 수, Claude↔Codex 전환 사유 | 사용량 때문에 중간 교대가 반복됨 |
| 인계 품질 | 새 세션 START만으로 이어졌는지, 다시 물은 항목 | 인계 누락으로 재작업 |
| 실패·보류 | 검증 실패, 발행 보호 중단, 자료 등록 보류의 건수와 원인 | 같은 원인 반복 |
| 도구 제약 | Orca에서 막힌 기능(OAuth·hot reload 등)과 우회 비용 | 우회가 상시화 |
| 대안 비교 | Orca 유지 / 일반 git worktree+터미널 / 담당 AI 재조정 중 위 신호를 줄이는 쪽 | — |

## 이번 체계 도입 당시 관찰(2026-10-19, Claude 세션)

- 한 세션이 길어져 사용량 사유로 Codex에 교대했다.
- 코드 반영마다 입력 보관 확인 → 안전 재시작 → push가 반복됐다.
- Windows 줄바꿈·Python 문자열 이스케이프로 문서 손상이 한 번 발생했다가 바로 복구됐다.
- 회사 결과 발행이 운영 자동 종가 갱신과 겹쳐 한 번 보호 중단됐다.
- Orca 세션은 비대화형이라 OAuth 인증·mods 즉시 적용 등이 제한된다.
- Claude 세션이 열린 상태에서 Codex가 같은 작업본에서 작업했다(Claude는 쓰지 않아 충돌 없음). 한 쓰기 세션 원칙은 기술적 잠금이 아니다.
