# PIT A단계 계정 확장 결과 (2026-11-04)

범위: 사용자 지시 "A단계 파서 확장". 개념 기준은 `design_financial_concepts_NICE_2026-11-04.md`(NICE 재무위험 평가)의 6~7절이다. 네트워크 요청은 0건이고, 이미 저장된 원문 14건(효성중공업 6, 롯데케미칼 4, 동아타이어공업 4)으로 검증했다.

## 만든 것
- **새 계정 18개**를 연결 재무제표에서 읽는다(현재 기간 열, 단위 환산, 원 단위 KRW).
  - 재무상태표: `total_assets`, `total_liabilities`, `short_term_financial_instruments`, `borrowings_current`, `borrowings_noncurrent`, `lease_current`, `lease_noncurrent`
  - 손익계산서: `finance_costs`, `pretax_income`, `income_tax_expense`, `net_income_total`
  - 현금흐름표(또는 손익): `interest_expense`, `depreciation`, `amortization`, `rou_depreciation`, `capex_tangible`, `capex_intangible`, `dividends_paid`
- **구조**: 새 모듈 `investment/pit_xml_accounts.py`가 읽고, `pit_xml.py`는 연결·병합만 한다. 값은 `pit_values` → `pit_annual` → `pit_verify`를 같은 이름으로 흐르고 범위 검사(자산·부채·차입금·리스·금융비용·상각·자본적지출·배당은 0 이상, 세전이익·법인세·순이익은 부호 자유)를 받는다.
- **원칙**: 새 계정은 *부드럽게* 처리한다. 이상이 있으면 문서를 막지 않고 그 필드(차입금·리스는 묶음 전체)만 빼고 `notes`에 사유 코드를 남긴다. 기존 5개 값(`revenue`, `operating_profit`, `ocf`, `equity`, `cash`)의 엄격한 오류 처리는 그대로다. 행이 없으면 0이 아니라 **필드 없음(미확인)**이다.
- **차입금·리스는 구간 인식**: `유동부채`/`비유동부채` 구간 안의 행을 합산한다. `단기`·`유동성`이 붙은 이름은 유동 구간에서만, `장기`·`비유동`이 붙은 이름은 비유동 구간에서만 허용하고, 목록에 없는 차입금성 이름이 섞이면 해당 묶음을 뺀다(`unclassified`).
- **부호**: 자본적지출·배당 지급은 회사마다 표기가 달라(효성·동아는 괄호 음수, 롯데는 양수) 유출 크기(절댓값)로 저장한다. 손실 라벨(`당기순손실` 등)은 0 이하일 때만 받는다. `법인세수익`은 지원하지 않는다.
- **`제N기` 형식 표**: 열 위치가 정확하므로 당기 칸이 채워져 있으면 뒤 칸이 비어도 받는다(실제 문서는 0인 과거 열을 빈칸으로 둔다). 옛 `(당)/(전)` 형식은 비어 있지 않은 칸 수가 열 수와 같아야 한다.
- 라벨 끝의 주석 번호 `(주14,31,35)`는 모든 계정 비교에서 제거한다(원래 5개 계정에도 적용).

## 검증
- 새 테스트: `tests/test_pit_xml_accounts.py` 41개(파서), `tests/test_pit_new_fields.py` 10개(매핑·투영·검증). 테스트를 먼저 썼고 Codex(`gpt-6-astra`)가 격리 사본에서 구현했으며 검토 후 적용했다.
- 기존 테스트 중 원래 5개 값을 "전체 딕셔너리"로 비교하던 단언은 새 필드가 같이 나오므로 5개 값만 보도록 바꿨다(의미 변경 없음). `look_alike` 테스트는 `자산총계`가 이제 실제 계정이어서 닮은꼴 이름 `자산총액`으로 바꿨다.
- 변이 53개를 준비해 51개를 실행했고(2개는 대상 문자열이 달라 건너뜀) 50개를 검출했다. 생존 1개는 동등 변이(`자산` 제목 행이 구간을 닫는 처리; 앞선 `자산총계`가 이미 닫음).
- 비-UI 전체 1423개 통과(스킵 3).
- 실제 문서 대조: 효성중공업 FY2025의 자산총계 7,227,883,006,296, 유동 차입금 337,991,108,202, 장기차입금 464,450,013,386, 부채총계, 금융비용, 법인세비용, 순이익이 문서 표시와 일치하고 세전이익 − 법인세비용 = 순이익이 성립한다.
- 파이프라인: 3개 회사 모두 `verify` 통과, 차단 0, G·C 불변(효성 19.36%·8.42%, 롯데 -6.03%·3.96%, 동아 5.40%·8.69%).

## 알게 된 것 (한계)
- **효성중공업 FY2023**: 같은 문서의 `제N기` 표에서는 유동부채 구간의 행 이름이 `장기차입금`(옛 표는 `차입금`)이어서 구간 불일치로 차입금 묶음을 뺐다. 보수적 동작이고 값은 옛 표에서 확인되지만 지금은 쓰지 않는다.
- **효성·동아의 리스부채**: 재무상태표 본문에 리스부채 행이 없다(효성은 기타금융부채 안). 행이 없다는 것이 "리스 없음"을 뜻하지 않으므로 0으로 두지 않는다. 따라서 이들 회사의 총차입금은 *리스 미확인* 상태이고, 문서 7절의 총차입금 정의(리스부채 포함)를 만족하지 못한다. 주석 확인(B단계)이 필요하다.
- **EBITDA**: 효성·동아 전 연도와 롯데케미칼 FY2023 이후는 현금흐름표가 조정 항목을 풀어 쓰지 않아 상각비를 본문에서 얻지 못한다. 이 경우 EBITDA는 미확인이다(주석 필요).
- **이자비용**: 롯데케미칼 FY2022만 현금흐름표에 이자비용이 있다. 나머지는 본문에서 얻지 못해 미확인이고, 현금 이자 지급(`이자의 지급`)으로 대체하지 않았다(확정 정의 5번).
- **법인세**: 롯데케미칼의 적자 연도는 `법인세수익` 라벨이라 법인세비용이 비어 있다. 유효법인세율의 예외 규칙은 아직 미결정이다.
- **금융비용**은 이자 외 외환손실·파생손실 등을 포함한 손익계산서 합계라 이자비용과 다르다. 이자보상 계열은 `interest_expense`가 있는 경우에만 계산해야 한다.
- 차입금 합산은 목록에 있는 이름만 합산하므로 `기타금융부채` 안의 차입 성격 항목은 잡지 못한다(B단계).
- 이 범위는 *원문에서 읽는 계정 확장*까지이고 총차입금, 순차입금, EBITDA, FCF 등 **파생 지표 계산은 아직 만들지 않았다**.
