## 구현 계약

이 문서는 Claude Code의 후속 구현 명세다. 이번에는 코드/실제 tests/fixtures를 생성하지 않았다. 아래 초안은 합성 자료이며 실기업·실제 시장경로가 아니다.

- **기존 계약 회귀**: 현재 코드가 지켜야 하는 동작. 기존 테스트와 중복되는 경우 새 테스트를 무조건 추가하지 말고 누락된 축만 확장한다.
- **강화 제안**: 아직 코드에 없는 과거 시점 적격성·공식 달력·비용/체결 계약. 현재 구현에 통과를 요구하거나 조용히 규칙을 바꾸지 말고 먼저 사용자의 채택을 받는다. 구현 전 실패는 기존 결함 확정과 구분한다.
- 시간 고정, 네트워크 차단, 운영 DB/파일 접근 금지. 임시폴더만 사용. 날짜는 합성 세션과 실제 KRX 세션을 명확히 구분한다.
- 각 케이스는 입력 SHA256·기준 commit·설정 해시·cutoff·seed·출처/가용시점·예상 상태·기대값·관측값을 보존. uuid/현재시각 등 비결정 필드는 비교에서 정규화한다.
- null/unknown/pending과 숫자0을 구분한다. 상태별 분모도 검증한다. 수익률·기여도 단위는 %와 %p를 구분하고 독립 산술 oracle 허용오차는 절대1e-8(부동소수 오차 외 정책 상한 완화 금지).

## tests/fixtures 초안 — 문서 안에만 보관

후속 위치 제안: `tests/fixtures/methodology/`. 아래 JSON은 기존 cache 스키마에 바로 넣는 파일이 아니라 어댑터가 읽을 테스트 명세 초안이다. 기존 `tests/test_portfolio_risk.py:10`의 risk_fixture와 `tests/test_research_followup.py:10`을 확장하되 실제 KRX 휴장일을 흉내냈다고 주장하지 않는다.

```json
{
  "schema": "methodology-scenario-draft-1",
  "id": "S13",
  "synthetic": true,
  "seed": 20261103,
  "calendar": {"kind": "synthetic_sessions", "warmup_prices": 253},
  "series": {
    "A": {"warmup_close": 100, "event_closes": [100, 110, 99]},
    "B": {"warmup_close": 100, "event_closes": [100, 90, 99]}
  },
  "weights_pct": {"A": 40, "B": 40, "cash": 20},
  "expected": {"daily_rebalanced_pct": 0, "initial_buy_hold_pct": -0.8},
  "risk_ids": ["R10"],
  "tolerance_abs": 1e-8
}
```

어댑터 규칙: A/B는 fixture 전용 6자리 코드로 매핑, 두 지수에 동일 합성 세션·index_level, 종목에 KRX/final/naver_chart_adjusted를 명시한다. 총 관측일 수는 warmup과 이벤트의 시작값 중복을 제거해 계산한다. `performance.created_on`은 이벤트 첫 기준종가 직전 세션, 평가일은 마지막 이벤트 종가다. 위험창은 이전 상수가 포함돼도 두 이벤트의 누적결과를 유지한다. 실자료 읽기·수집은 하지 않는다.

S01~S20 입력 변형은 base fixture를 deepcopy해 각각 독립 적용하고 입력 전후 digest 불변을 검사한다. S09 NaN/Inf는 Python 메모리 주입으로 테스트하고 비표준 JSON 상수로 파일에 쓰지 않는다. H계열 실데이터는 라이선스·공개 범위 검토 후 Git 제외 로컬 자료를 명시 참조하며 이 문서나 공개 fixtures에 복사하지 않는다.
