# PIT 확보율 개선: 별칭, 부호 항등식, 반올림 허용 (2026-11-04)

범위: 사용자 지시 "다음"(파서 확보율 개선). 외부 요청 0건, 저장된 원문으로만 작업했다. 직전 단계에서 점수가 안 나온 원인이던 삼성중공업·RFHIC의 계정 틈을 메운다.

## 1. 바꾼 것
1. **별칭 3개**: `단기리스부채`(유동 리스부채), `장기차입금(사채 포함)`(비유동 차입금), `당기연결순이익`(순이익).
2. **부호가 이름으로 정해지지 않는 행을 항등식으로 확정**: `세전이익 − 법인세비용 = 당기순이익`.
   - 이름이 `…순손실`인데 이익인 경우(삼성중공업 FY2025 `법인세비용차감전순손실` 650,478,606,939)와, 세금이 이익으로 표시된 `법인세수익`(RFHIC FY2023: 7,351,594,817 + 10,331,411,702 = 17,683,006,519)이 해당한다.
   - 후보 부호 조합 중 **정확히 하나**가 항등식(명세서 단위 3개 이내 오차)을 만족할 때만 확정한다. 해가 없거나 둘 이상이거나 항등식을 평가할 수 없으면 이전처럼 `sign_unclear`/`unsupported_label`로 제외한다. 중복 행 등으로 이미 사유가 붙은 값은 항등식에 쓰지 않는다.
3. **태그 값의 반올림 허용**: 같은 값을 원 단위 표(예: 311,797,002,761)와 천원 단위 표(311,797,003)가 담으면 239원 차이가 나서 `conflict`가 되었다. 큰 단위의 절반 이내이면 같은 값으로 보고 작은 단위(정밀한) 값을 쓴다. 본문 행과 태그 값의 비교도 태그 단위의 절반까지 허용한다.

## 2. 검증
- 테스트 먼저: 부호 항등식 11개, 별칭 3개 확장, 반올림 허용 5개 추가. 변이 검사 28개 중 24 검출, 생존 4개는 동등 변이(후보 순서 교환 2개, 값이 같은 필드를 다시 대입, 충돌 뒤 단위 정리).
- 비-UI 전체 1513개 통과(스킵 3).
- 이번 작업은 Codex 없이 직접 구현했다(기존 모듈에 규칙 몇 개를 더하는 규모).

## 추가: 새 형식 표의 빈 현재 칸 = 0 (2026-11-04, 사용자 "다음")
- **규칙**: `제N기` 형식 표에서 새 계정의 현재 칸이 비어 있고 뒤 칸이 채워져 있으면 현재 값을 0으로 읽는다(이전에는 `amount_count`로 제외). 모든 칸이 빈 행은 그대로 제목 행으로 무시하고, 열 수보다 칸이 많은 행은 `amount_count`다. 기존 5개 값의 엄격한 개수 규칙과 옛 `(당)/(전)` 형식 표의 규칙은 그대로다. 0과 0 후보(법인세수익 0)는 후보 부호 조합에서 중복을 제거해 모호하지 않게 처리한다.
- **근거(실제 문서 대조)**: 효성·삼성·RFHIC·롯데 문서 13건에서 같은 문서에 옛 형식 표와 새 형식 표가 함께 있는 행 중, 새 형식의 현재 칸이 비고 뒤 칸이 채워진 11개 행이 모두 옛 형식에서 `-`(0)로 표시됐다(예외 0건, 옛 형식 짝이 없는 24개 행은 판단에서 제외). 효성 FY2024 `배당금의 지급`도 같은 관행(0인 과거 열이 빈칸)이었다.
- **효과**: 저장된 기존 문서 14건에서 값이 바뀌거나 사라진 것은 0건, 추가된 값은 동아 FY2021 유동금융자산 0 하나. 삼성중공업 FY2022 `무형자산의 취득`이 읽혀 `notes`가 모두 사라졌다(삼성·RFHIC 8개 문서 모두 `notes` 없음).
- **검증**: 기존 테스트 3곳을 새 계약에 맞게 바꾸고(빈 현재 칸 → 0, 칸 초과 → `amount_count`) 새 테스트 5개 추가, 변이 6개 모두 검출, 비-UI 전체 1518개 통과.
- **주의**: 이 규칙은 "빈칸은 0"이라는 형식 관행에 기댄 판단이다. 형식이 달라지는 문서(빈칸이 미기재를 뜻하는 경우)가 나오면 값이 0으로 잘못 읽힐 수 있어, 이 규칙의 근거 대조(옛 형식 표와의 비교)를 새 회사를 추가할 때마다 반복하는 것이 안전하다.
