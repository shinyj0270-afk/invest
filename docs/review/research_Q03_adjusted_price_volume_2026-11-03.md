# Q03 조사 — 수정주가·거래량과 권리변동, 조정종가×거래량 근사의 한계

작성일: 2026-11-03. 조사 주체: Claude Code(직접 조사). 질문은 [research_questions.md](research_questions.md) Q03. 선행: [Q01](research_Q01_krx_pit_2026-11-03.md), [Q02](research_Q02_dart_vintage_2026-11-03.md).

## 조사 방법과 증거 등급

- KRX 규정 페이지와 OpenDART 개발가이드를 2026-11-03에 브라우저로 직접 열어 읽었다. **[직접]**
- 이 저장소의 코드·문서는 읽기 전용으로 확인했다. **[저장소]**
- **네이버 증권 페이지는 조사하지 못했다.** 내장 브라우저가 "safety restrictions"로 `finance.naver.com` 열기를 막았고, 웹 검색도 `naver.com` 도메인이 접근 불가였다. 다른 도구로 우회하지 않았다. 따라서 네이버의 공개 명세·도움말 유무는 **확인 불가**이며, 네이버 쪽 사실은 이 저장소의 기록(이전 세션이 남긴 문서·주석)에만 의존한다.

## 연구 결과

1. **거래소가 공개하는 조정은 "다음 거래일의 기준가격"에 한한다**(H1·H2). 이는 가격제한폭을 정하는 기준이며, 과거 가격 시계열 전체를 다시 쓰는 규칙(후방 조정)은 거래소 페이지에 없다. 후방 조정은 공급자가 정하는 가공이다.
2. **이론가격 조정 대상이 한정돼 있다.** 3자배정 유상증자와 일반공모 유상증자는 기준가 조정에서 빠진다(H1). 현금배당 처리는 확인되지 않았다(H5). 따라서 "거래소 기준가 조정 목록"과 "공급자 수정주가의 조정 범위"는 같지 않을 수 있다. 같은지는 확인하지 못했다.
3. **주식분할·병합은 OpenDART 결정 API가 없다**(H7). 분할·병합 이벤트의 구조화 소스는 거래소·KIND 쪽이 되는데, 이번에 해당 API나 파일을 확인하지 못했다. 이 항목은 **확인 불가**이며, "권리변동 oracle" 소스로는 미확정이다.
4. **실거래대금은 KRX가 직접 준다**(H6). 따라서 2010년 이후 구간에서는 `종가×거래량` 근사를 실제 거래대금과 대조할 수 있다. 다만 API 접근에는 키·약관 제약이 있다(Q01 F5).
5. **네이버 수정주가가 거래량도 같은 방식으로 조정하는지는 이번에 확인하지 못했다.** 이전 세션 기록은 가격의 분할 조정만 확인했다고 말한다(H10).

## 산식 분석 [AI 해석 — 관측값 아님]

기호: 이벤트 전 실제 종가 c, 실제 거래량 v, 조정계수 f(분할 비율 등). 설명용 수치는 KRX의 분할 예시(H2, 1:10)를 그대로 썼다.

| 경우 | 이벤트 전 일자의 조정종가 | 이벤트 전 일자의 거래량 | 조정종가×거래량 | 실제 거래대금 c·v 와의 관계 |
|---|---|---|---|---|
| 분할(f=10), 가격·거래량 **모두** 조정 | c/10 | v×10 | c·v | 같음 |
| 분할(f=10), 가격만 조정·거래량 **원값** | c/10 | v | c·v/10 | **1/10로 과소** → 이벤트 전후 거래대금 변화율이 가짜로 +900% 방향 |
| 분할(f=10), 거래량만 조정 | c | v×10 | 10·c·v | 10배 과대 |
| 현금배당 후방 조정(가격만 배당률만큼 낮춤) | c×(1−d) | v | c·v×(1−d) | 배당수익률 d만큼 과소(배당 큰 종목에서 영향) |

- 첫 행처럼 둘 다 조정되면 근사가 이벤트 구간에서도 성립한다. 가격만 조정되면 이벤트 구간을 가로지르는 VWAP·거래대금 변화가 이벤트 효과로 오염된다.
- 저장소 코드는 어느 경우인지 검사하지 않는다(H11). 네이버가 어느 쪽인지 확인하지 못했으므로(위), 이 표는 "근사가 안전한 조건"을 정리한 것이지 현재 오염 여부를 판정한 것이 아니다.
- 유상증자(권리락)는 조정계수가 이론가격 산식에 의존하고 신주 가격·배정비율이 필요하다(H1, H3). 3자배정·일반공모는 거래소 기준가 조정 대상이 아니므로(H1) 가격에 불연속이 남을 수 있다.

## 우리 시스템에 대한 해석 [AI 해석]

- `adjusted_close_volume_proxy`가 "실제 체결 VWAP/거래대금"이 아니라는 표기(H11)는 올바르다. 그 위에 이벤트 구간의 정합성(가격·거래량의 같은 조정)이 별도 조건으로 필요하다.
- 가격수익률 계열은 가격 조정 방식(분할 조정만인지, 배당까지 포함하는 총수익인지)을 라벨로 구분해야 한다. 저장소 라벨 `naver_chart_adjusted`는 "무엇을 조정했는지"를 말하지 않는다(H10). 가격/총수익 라벨 계약(아래)을 제안한다.
- 권리변동 oracle이 필요하다. 소스 후보: KRX 규정의 이론가격 산식(별표, 이번에 미열람), 거래소 일별 실거래대금(H6), OpenDART 증자·감자·합병·분할 결정(H7)과 배당 사항(H8). 분할·병합은 후보 소스 미확인.

## 아직 검증할 가설

- H-a: 네이버 일봉의 과거 거래량은 분할 때 가격과 같은 비율로 조정된다. (가격 조정은 저장소 기록상 표본 확인)
- H-b: 네이버 수정주가는 현금배당을 반영하지 않는다(가격수익률만).
- H-c: 네이버는 3자배정·일반공모 유상증자와 무상증자·감자를 서로 다르게 처리한다.
- H-d: 2010년 이후 구간에서 `수정종가×수정거래량`이 KRX 실거래대금과 이벤트 없는 일자에는 근접하고, 분할 전후 일자에는 괴리한다.

## 채택 전 최소 데이터·테스트

1. T1 (H-a·H-d): 사용자가 KRX OPEN API 키를 신청한 뒤, 분할 이력이 있는 종목 1~2곳(예: 이전 세션이 표본으로 쓴 삼성전자 2018-05)에 대해 이벤트 전후 각 5거래일의 KRX 실거래대금·원종가·거래량을 받아, 네이버에서 저장한 `close·volume`과 나란히 비교한다. 네이버 데이터 수집은 사용자가 기존 경로로 이미 갖고 있는 값을 쓴다.
2. T2 (H-b): 배당락이 있었던 일자 3개를 골라 KRX 원종가 대비 네이버 수정종가의 전일 대비 변화율이 현금배당만큼 조정됐는지 본다.
3. T3 (H-c): 무상증자 1건, 3자배정 유상증자 1건, 감자 1건에 대해 같은 방식으로 비교한다. OpenDART 증자·감자 결정 API(H7)로 이벤트 일자와 비율을 확보한다.
4. T4: KRX 업무규정 시행세칙 별표1·별표1의4(이론가격 산식)를 사용자가 열어 산식을 문서에 옮기거나 KRX에 문의한다.
5. T5: 분할·병합 이벤트의 구조화 소스를 확인한다(KIND 공시 유형 또는 거래소 데이터 상품). 본 조사에서는 찾지 못했다.
6. T6: [test_scenarios.md](test_scenarios.md) S06·S07·S19를 위 소스로 만든 corporate-action oracle과 연결한다.

## 필요 입력 필드 (가격/총수익 라벨 계약 제안)

- 가격 계열 메타: `price_basis` ∈ {raw, split_adjusted, split_and_rights_adjusted, total_return}, `volume_basis` ∈ {raw, adjusted_with_price, unknown}, `dividend_adjusted`(bool/unknown), `adjustment_source`, `adjustment_spec_status` ∈ {published, partially_known, unknown}, 수집 시각.
- 이벤트 원장: 이벤트 종류(분할·병합·무상·유상(방식 구분)·감자·합병·분할)·권리락/배당락일·조정계수 또는 비율·산식 출처(규정 별표 또는 공시 접수번호).
- 대조용: 일별 실거래대금(KRX), 이벤트 구간 flag.

## 기존 구현과의 차이와 도입하지 않을 이유

- 기존: 가격 조정 라벨 `naver_chart_adjusted`, 거래대금 proxy 표기(H10·H11).
- 차이: 라벨이 가격 조정의 범위·거래량 조정 여부를 말하지 않는다. 이 조사에서 거래량 조정 여부는 확인하지 못했다.
- 도입 보류 이유: ①네이버 명세·관측을 확인하지 못함, ②분할·병합 소스 미확인, ③KRX 이론가격 산식 별표 미열람. T1~T5 전에는 라벨 체계나 이벤트 구간 처리 규칙을 코드에 반영하지 않는다.
