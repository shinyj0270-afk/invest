범위: 사용자 승인 "1,2번 승인 및 진행". 2번 = 삼성중공업·RFHIC 추가(승인된 요청 목록), 1번 = 파생 지표를 품질 점수에 연결.

- **결과**: 두 회사 모두 12월 결산, 연속 4개 연도, 연결재무제표 있음(RFHIC 포함). 4개 연도 파싱, `verify` 통과, 차단 0. 필드 확보는 15~18개이고 EBITDA는 상각비를 본문에서 얻는 FY2025에서만 나온다(삼성중공업·RFHIC).

## 2. 점수 연결: `investment/pit_factors.py`
- G·C는 기존 `pit_quality.partial_factors` 결과를 그대로 쓰고, **Q**와 **B**를 추가한다. 점수는 `S_pit_QGCB` = 100 × (0.30 Q + 0.25 G + 0.20 C + 0.10 B) / 0.85(기존 가중치 재정규화). V는 가격이 필요해 계산하지 않는다. `quality_score`/`S_long`은 쓰지 않고 기존 `S_pit_GC`도 그대로 둔다.
- **Q**: 4개 연속 연도의 ROIC 3개 중앙값. ROIC = 영업이익 × (1 − 유효법인세율) / 평균 투하자본, 투하자본 = 자기자본 + 순차입금(`pit_metrics`).
- **B**: 최신 연도 −순차입금/자기자본.
- **법인세 예외 규칙(제안, 사용자 확인 필요)**: 세전이익 ≤ 0이면 세율 0, 세전이익 > 0이면 `법인세비용/세전이익`이 0~1이어야 하며 벗어나거나 법인세비용이 없으면 그 연도는 사용 불가. 법정세율로 대체하지 않는다. 적자 연도는 `approximations`에 `tax_rate_zero_for_loss`로 기록된다.
- **순차입금 사용 기준**: 기본은 `ok`일 때만. `tolerated=LIQUID_UNDERSTATEMENT`를 주면 "단기금융상품·유동금융자산이 없어 순차입금이 상한인 경우"만 허용하며, 허용한 근사는 결과의 `approximations`에 남는다. 리스부채 미확인이나 차입금 누락은 허용하지 않는다.
- **검증**: 계약 테스트 22개(테스트 먼저, Codex 구현, 검토 후 적용, BOM 제거와 근사 기록 규칙 수정은 제가 반영), 변이 47개를 준비해 43개를 실행(4개는 문자열 불일치로 건너뛰었고 허용 사유 집합은 정확한 내용을 비교하는 테스트로 따로 고정)했고 36개를 검출했다. 생존 7개는 동등 변이(이미 걸러지는 조건, 연결된 두 줄, `num()` 필터 중복). 비-UI 전체 1497개 통과.

## 4. 파서 확보율을 막는 구체적인 계정 이름 (다음 작업 후보)
- RFHIC: `단기리스부채`(유동 리스부채 별칭 없음), `장기차입금(사채 포함)`(비유동 차입금 별칭 없음, 현재는 "목록에 없는 차입금성 이름"으로 차입금 묶음 전체가 제외됨), 세금 항목이 `법인세수익` 라벨(지원하지 않는 라벨).
- 삼성중공업: FY2025 손익계산서의 `법인세비용(수익)` 행이 옛 형식에서 전기 칸이 비어 금액 개수 규칙(`amount_count`)에 걸린다.
- 공통: `법인세수익`(세금 이익) 부호 규칙을 정하면 롯데·RFHIC의 세율이 살아난다.
- 효성중공업: 유동 `기타금융자산`에 단기금융상품이 섞여 있어 유동금융자산을 본문에서 얻지 못한다(주석 필요).
