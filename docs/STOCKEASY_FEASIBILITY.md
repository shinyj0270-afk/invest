## 후속 확정 범위 · 2026-09-30

사용자 요청으로 ETF·미국장·AI 리서치/대화·동일 전략/수익률·사이트 전체 저장·당장 실시간 연결은 제외했다. 아래 최초 조사의 관련 항목은 참고 기록이며 실행 범위가 아니다.

기업 발굴(수익성·재무·PER/PBR) → 간단 분석 → 추세 확인을 중심으로 구현했다. 관심목록·산업별 비교·저장 공시/뉴스 원문 연결과 기존 최대 5종목 포트폴리오를 활용한다. RS는 **가격 추세 순위 주지표 + 지수 초과수익 보조지표**로 확정했다. 정의·표본 한계·구현 범위는 [FUNDAMENTAL_DASHBOARD.md](FUNDAMENTAL_DASHBOARD.md)에 기록했다. 현재 부족한 시장 데이터와 PER/PBR 원자료는 결측 사유로 남는다.

## 1. 결론

**화면의 정보 구성과 일반적인 탐색 기능은 자체 코드로 구현할 수 있다. 기존 통합 대시보드에도 재사용할 기반이 있다. 가장 큰 제약은 전 시장 데이터, 공개되지 않은 분석 규칙, 콘텐츠 재사용 권한이다.**

이번 조사에서 말하는 “가능”은 화면이나 기능을 우리 데이터와 코드로 새로 만드는 기술적 가능성이다. 원본 HTML·CSS·JavaScript·로고·문구·데이터를 그대로 가져와도 된다는 뜻은 아니다. 동일 결과의 재현 여부와 이용조건은 별도로 판단한다.

권장 순서는 **종목 탐색·요약 화면 → 업종 비교·공시 타임라인 → 데이터 확보 후 RS·신고가**다. 현재 분석 엔진과 Infomax 우선 원칙을 유지하면서 필요한 화면을 추가하는 방식이 적합하다.

## 4. 그대로 가져오기 어렵거나 현재 확보할 수 없는 것

### 4.1 원본 콘텐츠·데이터 사용권

약관 제7조 ②는 회사가 제공한 콘텐츠·데이터·분석 자료의 권리를 회사에 귀속시키며, 사전 동의 없는 복제·배포·상업적 이용을 제한한다. 제6조는 지식재산권 침해와 서비스 부하 유발도 금지한다. 원칙적으로 무료라는 제4조의 설명은 재사용 허가와 다르다.

따라서 **개인 대시보드용이라는 사유만으로 데이터·분석문·원본 코드의 일괄 복제가 허용된다고 전제할 수 없다.** 원본 활용이 필요하면 대상 자료·저장·변형·갱신·사용 범위에 대한 권한을 별도로 확인해야 한다. 이는 확인한 약관에 따른 작업 범위 판단이며, 특정 화면의 법적 보호 범위를 확정한 결론은 아니다. [이용약관](https://stockeasy.intellio.kr/terms)

### 4.2 원본 전략의 동일한 판단과 성과

운영자 방법론은 세 전략의 구체적인 매매 조건·임계값을 비공개로 명시한다. 공개된 RS 조건 일부만으로 전체 전략을 복원할 수 없다. 같은 화면과 비슷한 전략을 만드는 것과, 동일 날짜에 같은 종목·매수가·매도가·성과를 만드는 것은 다르다. [전략 방법론](https://stockeasy.intellio.kr/guide/strategy-room)

또한 사이트 전략 성과는 개별 실현손익률과 미실현손익률을 더하는 방식이라고 설명한다. 이를 우리 실제 포트폴리오 수익률로 표시하면 의미가 달라진다. 우리 화면에서는 평가손익률, 자본을 반영한 전략 수익률, 모의 결과를 구별해야 한다. [전략실](https://stockeasy.intellio.kr/strategy-room)

### 4.3 내부 시스템

로그인 화면을 볼 수 있어도 서버 코드·원본 DB·AI 프롬프트·전체 수집 과정·운영 인프라까지 얻을 수 있는 것은 아니다. 공개된 화면만으로 원본 서버와 같은 성능·갱신주기·정확성을 보장할 수 없다.

조사한 메뉴·가이드·검색 범위에서 외부 이용자를 위한 API 계약/문서를 확인하지 못했다. “API가 없다”는 단정은 하지 않는다. 사이트 내부 통신이 존재하더라도 외부 제품에서 계속 이용할 권한이나 안정된 계약이 있다는 근거로 삼지 않는다.

### 4.4 외부 사이트를 iframe으로 넣는 방식

로그인·쿠키·임베드 정책·외부 사이트 변경에 종속된다. 이번에는 해당 서버의 프레임 허용 헤더와 실제 임베드 동작을 검사하지 않았으므로 기술적으로 가능/불가능을 확정하지 않는다. 설령 표시가 가능해도 우리 필터·보유·분석 엔진과 데이터가 통합되는 것은 아니다. 1차 구현안은 자체 화면으로 구성하는 편이 목적에 맞는다.

## 5. 현재 INVESTMENT와 연결할 때 중요한 차이

### 이미 활용할 수 있는 기반

- `src/workspace.html`, `src/workspace.css`, `src/workspace.js`: 통합 개요, 기업 선택, 시장/산업 필터, 12개 메뉴, 비교 시각화, CSV와 인쇄.
- `src/engine.js`, `src/portfolio_engine.js`: 조건검색·재무 분석과 보유 평가·구성 검토.
- `investment/live_dashboard.py`, `investment/auto_refresh.py`, `investment/infomax_provider.py`: 로컬 서버와 Infomax 저장자료 갱신.
- `investment/trend.py`: 이동평균·벤치마크 대비 수익·변동성 축소·돌파 분석.
- `investment/market_events.py`: 공시/뉴스의 출처·발표일·검토 상태 저장.

### 기존 기능만으로 채워지지 않는 부분

1. **현재 갱신은 Infomax 저장파일 확인이다.** `SavedDailyProvider`/`SavedSnapshotProvider`가 파일을 읽는다. 브라우저에 실시간 표시를 붙여도 단말 직접 연동이나 실시간 시세 공급이 생기지 않는다.
2. **분석 대상은 국내 비금융 보통주다.** `eligible()`는 KOSPI/KOSDAQ, ordinary, nonfinancial 조건을 사용한다. 금융업·ETF·미국장을 단순히 메뉴에 추가하면 일부 데이터가 제외되거나 기존 판단식과 맞지 않는다.
3. **코드 규칙은 6자리 숫자다.** ETF의 영문 혼합 코드 및 미국 티커는 스키마, Python·JavaScript 검증, 식별자 연결을 함께 확장해야 한다.
4. **비교 화면은 최대 30기업이다.** `scope()`가 선택 결과의 앞 30개를 사용한다. 그 표본을 전 시장 업종 비중·랭킹·시장신호로 표시하면 안 된다. 시장 집계는 별도로 계산하고 화면 표시 개수와 분리해야 한다.
5. **기존 RS는 다른 지표다.** `trend.py`는 126/252거래일 벤치마크 초과수익의 표본 내 백분위를 60/40으로 결합한다. 스탁이지 안내의 최근 분기 가중 12개월 상대강도와 다르다. 기존 값을 스탁이지 RS와 같다고 이름 붙이지 않는다. [RS 안내](https://stockeasy.intellio.kr/guide/rs)
6. **가격 저장과 충분한 이력 확보는 다르다.** 현재 추세 엔진은 253개 공통 거래일·조정 OHLCV·벤치마크가 없으면 unknown을 반환한다. 가격선/신고가/RS에는 실제 유효 이력을 확보해야 한다. 일반 `prices` 계약과 추세용 `trend_prices` 경로도 함께 점검한다.
7. **공시·뉴스 기능은 있으나 통합 HTML에는 아직 직접 편입되지 않았다.** 현재는 Streamlit 경로를 사용한다. 뉴스 공급 범위는 삼성전자 공식 뉴스룸과 설정된 DART이며 전체 뉴스 시장이 아니다.
8. **개인 입력은 대부분 세션에 머문다.** 현재 HTML은 보유를 서버로 전송하지 않고 갱신 시 일시 복원한다. 관심목록·연구·이력을 지속 저장하려면 PC별 저장과 내보내기 범위를 설계해야 한다.
9. **PER/PBR 메뉴가 계산 완료를 의미하지 않는다.** `workspace.js`에는 두 항목의 표시 정의가 있지만, `val()`은 `row.metrics`의 값을 그대로 읽고 공통 `METRICS` 및 JSON 스키마에는 두 키가 없다. 현재 구조에서 완성된 밸류에이션 기능으로 간주하지 않고 원자료·계산 기준·검증 계약을 연결해야 한다.

기존 PROJECT_STATE에는 실제 저장 3종목·2026-09-23 가격과 가격 이력 부족이 기록돼 있다. **이번 조사는 개인 DB·원자료를 다시 읽지 않았으므로 현재 데이터량을 재검증한 결과로 보지 않는다.**

## 6. 권장 1차 적용안

### 1단계: 현재 데이터로 완성 가능한 화면

- 공통 종목 검색과 최근 선택 기업 접근.
- 기업 요약 카드와 원수치/출처 확인, 상세 분석 이동.
- 관심종목 목록과 기존 보유 평가의 빠른 접근.
- 현재 보유한 종목 범위의 업종·시가총액 구성도. “전체 시장”으로 표현하지 않음.
- 데이터 기준일·유효 기업 수·결측·갱신 상태를 각 카드에 표시.

**완료 기준:** 화면의 숫자가 기존 엔진 결과와 일치하고, 기존 필터·선택·보유 입력이 메뉴 이동과 갱신 후 보존되며, 부분 표본을 시장 전체로 표시하지 않는다.

### 2단계: 기존 기능의 통합과 데이터 범위 확대

- Streamlit의 공시·뉴스 및 추세 연구 결과를 통합 화면에서 연결.
- 사용할 종목 모집단, 거래소·수정주가·거래일 기준 확정.
- 가격 이력과 벤치마크 확보 후 RS·52주 신고가 구현.
- 당일 시장 전체 수급과 업종 흐름은 별도 입력 계약으로 연결.

**완료 기준:** 과거 시점에서 미래 자료를 사용하지 않으며, 신규상장·거래정지·결측·비확정 시세를 구별한다. [신고가 안내](https://stockeasy.intellio.kr/guide/new-high)는 화면 기능 조사 근거로만 사용하고 계산 기준은 우리 문서에서 명시한다.

### 3단계: 별도 제품 범위에 해당하는 확장

- ETF·미국장: 식별자·통화·거래시간·자산별 지표부터 확장.
- AI 리서치: 자료 사용권·근거 문서·모델 비용·재현 가능한 검증 마련.
- 자체 전략 성과: 실제 자본과 거래비용을 반영하는 모의 성과 기록 설계.

이번 요청에는 구현·자동매매·예약 실행·배포를 포함하지 않았다. 데이터 계약이 정해지기 전 “사이트 전체 복제”에 소요되는 기간을 확정하지 않는다. 1단계는 주로 화면 작업이고, 2·3단계는 데이터 및 계산 작업의 비중이 크다.
