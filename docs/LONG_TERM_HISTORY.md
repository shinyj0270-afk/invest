# 장기 실적 연결

인포맥스의 연결·단독분기 손익을 현재 시점에 조회해 연간 추이, 매출 3년·5년 CAGR, 최근 4분기 매출·영업이익·지배주주 순이익을 표시한다. 앱의 **기업분석 → 장기 실적 · 현재 조회본**과 **장기성장 연구 → 현재 조회본의 장기 실적**에서 확인한다. A4 보고서에는 조회일과 두 성장률이 표시된다.

## 현재 자료

- 삼성전자·SK하이닉스·현대차, 2018년 3분기~2026년 2분기, 기업당 32개 분기.
- 완료 연도는 2019~2025년, 기업당 7개. 일부 분기만 있는 2018년과 2026년은 연간 합계에서 제외한다.
- 단위는 인포맥스 천원을 원으로 변환하고, 화면의 금액은 억원으로 표시한다.
- 연간 실적은 해당 연도의 4개 단독분기 합계다. 3년 성장률은 2022~2025년, 5년 성장률은 2020~2025년 매출을 사용한다.
- 2025년 매출·영업이익·지배주주 순이익 9개 합계는 세 기업의 공식 연간 연결보고서와 모두 일치했다. 대조한 PDF 위치와 해시는 로컬 검토 파일에 기록했다. 나머지 모든 연도를 공시와 개별 대조한 것은 아니다.

## 시점과 적용 범위

현재 조회본의 과거 실적과 과거 공시 당시에 알 수 있던 자료는 다르다. 공개일을 추정해서 넣지 않는다. 확장 자료는 `observed_financial_history`에 보관하며 기존 `annual`, `quarters`와 공개 시점 기준 연구 판정을 바꾸지 않는다. CAGR·TTM의 현재 조회본 사용은 앱에서 명시적으로 선택한 계산 경로다. 기본 `additional()`과 기존 연구 배치는 이 자료로 과거 시점 신호를 만들지 않는다.

기존 42개 기본 수치, 8개 분기 재무 근거, 일별 가격·수급은 보존한다. ROIC·현금흐름·배당 성장과 조정 OHLCV·벤치마크는 이번 확장에 포함되지 않는다. 일상 갱신 버튼은 장기 실적과 원래 조회일을 유지한다. 새 재무 파일을 저장하는 것만으로 장기 실적이 재검토·반영되지는 않는다.

## 다음 재무 갱신 시

1. 기존과 같은 연결·순·연속분기 IMDH 조회를 저장한다. 매출·영업이익·지배순이익 필드와 단위를 유지한다.
2. 최신 분기의 기존 재무 연결을 검토하고, 최신 완료 연도의 공식 보고서 금액·PDF 위치·해시를 검토 JSON에 기록한다.
3. 새 출력 이름으로 변환한 뒤 명시적으로 DB에 가져온다. 입력 파일은 덮어쓰지 않는다.

```powershell
.\.venv\Scripts\python.exe tools/infomax_history.py --base <기준스냅샷.json> --income <장기손익.xlsx> --review <검토.json> --output <새스냅샷.json>
.\.venv\Scripts\python.exe batch.py import-file --profile <이PC프로필> --mode user_input --file <새스냅샷.json>
```

입력의 종목 집합, 분기 연속성, 결측, 완료 연도 수, 기존 검토 분기와의 차이를 검사한다. 기존 분기와 1억원 이상 달라지면 재검토를 위해 중단한다. 공식 연간보고서와의 차이는 인포맥스 우선 정책에 따라 차이와 허용 오차 여부를 모두 보존한다. 로컬 원자료·검토 JSON·스냅샷·DB는 Git 공유 대상이 아니다.
