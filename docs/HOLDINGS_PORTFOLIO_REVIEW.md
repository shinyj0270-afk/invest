## 결론

세 화면의 역할은 구분되어 있습니다. 보유 수량·매입가·현금과 연구 근거를 입력하고, 현재 평가손익을 확인한 뒤, 조건에 맞는 모의 구성안을 비교하는 흐름입니다. 핵심 배분 제약과 손익 합계는 검사에서 통과했습니다. 실사용에는 **화면 간 설정 일치, 평가일 안내, 쉬운 연구 입력, 입력 보관, 현재 보유와 목표안 비교**가 필요합니다.

## 우선 수정할 오류 3건

### 1. 평가손익 기여가 사용자가 정한 가격 유효기간을 무시함

- 보유 화면은 포트폴리오의 구성 설정을 적용합니다. 평가손익 기여 화면은 설정을 전달하지 않아 기본값인 가격 경과일 4일을 사용합니다.
- 가상 재현: 평가일 2026-10-01, 가격일 2026-09-23, 사용자가 가격 경과일을 10일로 설정. 보유 평가액은 **1,150,000원**, 같은 입력의 평가손익 기여 화면은 **자료 대기**입니다.
- 수정 방향: 세 화면이 같은 입력·평가일·가격 설정을 읽게 합니다. 설정을 바꿔 자료가 유효한 것처럼 만들라는 뜻이 아닙니다. 실제 사용 시 최신 가격과 출처 확인이 먼저입니다.
- 위치: `src/workspace.js:54`의 `PortfolioEngine.reviewHoldings(data)`.

### 2. 통합 화면에서 평가일·자료 범위 안내가 숨겨짐

- 내보내기에서 `.scope-bar` 전체를 숨겨 보유 화면의 `pScope`도 보이지 않습니다. 평가 기준일, 저장 시장자료 날짜, 입력 범위와 과거 평가일 경고가 함께 숨겨집니다.
- 가상 2026-09-25 평가일을 2026-10-01에 열었을 때 과거일 경고가 화면에 나타나지 않는 것을 재현했습니다. 이용자는 오늘 기준 검토로 오해할 수 있습니다.
- 수정 방향: 보유 전용 안내는 표시하고 기존 조건검색의 중복 안내만 필요한 범위에서 숨깁니다.
- 위치: `investment/workspace_export.py:48`의 `.scope-bar{display:none}`.

### 3. 구성 설정 오류 시 이전 검토 건수가 남음

- 최대 기업 수를 빈칸으로 바꾸면 보유 표는 설정 오류로 계산을 중단합니다. 상단의 재검토·매도 검토 **2건**, 판단 보류 **1건**은 이전 값 그대로 남습니다.
- 수정 방향: 재계산 실패 시 평가액, 건수, 상세 근거와 이전 결과 표시를 함께 초기화하고 어떤 설정을 고쳐야 하는지 알려줍니다.
- 위치: `src/portfolio_ui.js:80`의 `refresh()` 예외 처리.
