# 회사·집 보유내역 자동 동기화

기본 입력은 **보유 직접 입력**이다. **보유·가격·현금 반영**을 누르면 먼저 입력을 보관하고, 연결 앱에서는 GitHub의 보유 전용 비공개 저장소로 자동 전송한다. 앱을 다시 열면 저장된 입력을 복원한다. 열린 앱은 약 20초마다 다른 PC의 변경을 확인한다. 입력 파일은 백업·최초 이전·수동 복구에 사용한다.

## 회사 PC에서 사용

1. 처음 옮길 때만 기존 HTML의 **현재 입력 내보내기**로 보관한다. 기존 화면을 먼저 새로고침하지 않는다.
2. 프로젝트의 **scripts/open-investment.cmd**를 두 번 클릭한다. 회사 PC의 출력 폴더에도 **통합투자대시보드-동기화.cmd** 실행파일을 제공한다.
3. 열린 앱의 **보유 입력·검토**에서 입력 파일을 불러오거나 종목을 직접 입력한다.
4. **회사·집 동기화 완료** 표시를 확인한다. 현금이 없으면 0을 입력한다. 이후에는 보유내역을 다시 입력할 필요가 없다.

브라우저에서 사용하는 주소는 `http://127.0.0.1:8767/`이다. 실행파일은 이 PC의 서버를 백그라운드로 열며 기존 서버가 있으면 확인 후 재사용한다. 다른 프로그램이 같은 포트를 쓰면 중단한다. Windows 예약 작업이나 PC 부팅 자동 시작은 등록하지 않는다.

## 집 PC의 최초 설정

1. 기존 INVESTMENT 작업본이 깨끗한지 확인한 뒤 최신 main을 받는다. 로컬 수정은 먼저 보존한다.
2. 이 PC의 `.venv`, Node.js와 GitHub CLI가 필요하다. 기존 개발 환경을 사용하며 회사 PC의 실행 환경·인증 파일을 복사하지 않는다.
3. GitHub CLI에서 **shinyj0270-afk** 계정으로 한 번 로그인한다. 해당 비공개 저장소의 읽기·쓰기 권한이 필요하다.
4. 같은 **scripts/open-investment.cmd**를 실행한다. 회사 PC에서 저장한 내용이 자동 복원된다. 보유 JSON을 매번 옮길 필요가 없다.

최초 로그인 또는 접근 권한이 없으면 **연결 대기**로 표시한다. 집 PC의 실제 실행·로그인 여부는 회사 PC만으로 확인할 수 없다.

필요할 때 프로젝트 폴더에서 실행하는 명령:

```powershell
gh auth login --hostname github.com --web
.\.venv\Scripts\python.exe tools\open_dashboard.py
```

PowerShell 스크립트를 사용할 경우 `scripts/open-investment.ps1`도 제공한다. 실행 정책을 바꾸거나 우회할 필요가 없는 `.cmd` 실행파일을 기본으로 사용한다.

## 어떤 내용이 유지되는가

- 보유종목·수량·평균 매입가·현금·입력 메모
- 연결된 연구 입력과 사용자가 입력한 가격·기준일·출처
- 포트폴리오 구성 설정

현재가·날짜·출처는 한 묶음으로 병합한다. 서로 다른 종목이나 같은 종목의 서로 다른 항목을 수정하면 변경사항을 합친다. 같은 항목을 다르게 수정하거나 한쪽이 지우고 다른 쪽이 수정하면 **충돌**을 표시한다. 자동 덮어쓰기를 멈추고, **내 입력 적용 / 다른 PC 값 적용** 중 선택한 항목만 반영하며 충돌 없는 변경은 유지한다.

**입력 비우기 / 보유 삭제 / 파일 불러오기**는 저장 및 다른 PC에 반영되는 명시적 변경이다. 가상 예제는 실제 보유 동기화에 넣지 않는다. **저장된 내 보유내역으로 돌아가기**로 복원한다. 화면에 입력 중이지만 아직 반영하지 않은 값은 원격 확인 때문에 지우지 않는다. 자동 보관 대상은 형식 검사를 통과해 반영한 값이다.

## 연결이 끊겼을 때

브라우저에 입력과 전송 대기 상태를 먼저 보관한다. 서버에 도달한 입력은 이 PC의 `.local/holdings-sync/cache.json`에도 남겨 재시작 뒤 재전송한다. 다시 연결되면 최신 원격 상태와 비교해 전송한다. 실패 시 재시도 간격을 늘리고, 저장이 차단된 경우에는 **현재 입력 내보내기** 안내를 표시한다. 성공하지 않은 전송을 완료로 표시하지 않는다.

## 저장 범위와 실행 방식

공개 코드 저장소 `shinyj0270-afk/invest`에는 보유내역을 넣지 않는다. 사용자가 선택한 전용 저장소 `shinyj0270-afk/invest-holdings-private`의 비공개 여부와 쓰기 권한을 실제 전송 전에 확인한다. GitHub 인증은 각 PC의 GitHub CLI가 처리하며 HTML·보유 파일·공통 설정에는 토큰을 넣지 않는다. 계좌번호와 증권사 비밀번호는 필요 없다. 원자료·DB·인증키와 기존 설정을 함께 동기화하지 않는다.

**연결 앱이 자동 동기화의 기본 실행 방식**이다. 저장 HTML을 단독으로 열면 해당 브라우저에 자동 저장한다. 파일 경로나 브라우저가 달라지거나 브라우저 저장소를 지우면 별도 저장 범위가 될 수 있으므로 PC 간 사용은 연결 앱을 연다. 브라우저 보관이 차단돼도 서버 저장이 확인되면 동기화 결과를 표시하며, 둘 다 실패하면 파일 보관을 안내한다.

앱 시작은 저장 시장자료를 읽기만 한다. **데이터 새로고침** 버튼은 기존 자료 갱신 기능을 호출한다. 보유내용 저장이 최신 시세 조회나 기업 검토 완료를 뜻하지 않는다. 가격이 오래되거나 연구 근거가 부족하면 기존 계산·판정의 대기 조건을 유지한다.

구현은 [GitHub Contents API](https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents)의 현재 파일 SHA를 붙여 수정한다. 다른 PC가 먼저 저장하면 최신 값을 다시 읽고 병합한다. 강제 덮어쓰기는 사용하지 않는다. `.local` 파일·입력 JSON·개인 보유내용은 공개 코드 인계 목록에 포함하지 않는다.
