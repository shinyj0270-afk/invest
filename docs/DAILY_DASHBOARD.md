# Daily Dashboard

## 시작

```powershell
.\.venv\Scripts\python.exe tools/serve_dashboard.py
```

브라우저에서 `http://127.0.0.1:8767/`을 연다. Infomax 저장자료 확인·갱신과 기업 비교를 함께 제공하는 기본 화면이다. 장기성장·추세 연구, 공시·뉴스, 기존 일일 요약은 필요할 때 `.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1`로 연다. 두 명령 모두 각 PC의 `.venv`를 사용하며 기본 통합 화면의 보유·포트폴리오 계산은 브라우저에 내장된 기존 JavaScript 엔진을 사용한다.

## 기업 발굴과 RS

기본 첫 화면은 **수익성 · 가치 조건검색**이다. ROE·영업이익률·매출 증가율 하한, 부채비율·PER·PBR 상한, 가격 추세 순위 하한과 추세 조건을 직접 적용한다. 검색은 저장된 적격 기업 전체에 적용하며 25개씩 표시한다. CSV는 페이지와 무관하게 필터 결과 전체를 포함한다. 기존 비교 차트 메뉴의 최대 30개 범위는 유지된다.

기업명을 누르면 **간단 분석**, **추세 확인**으로 이동한다. 가격 추세 순위를 주지표로 표시하고 6/12개월 지수 초과수익을 보조지표로 함께 제공한다. 순위는 같은 거래소의 저장 유효 기업 내 백분위이며 전체 시장 RS가 아니다. 현재 수치와 일치하지 않는 PER/PBR은 결측 사유를 확인할 수 있다.

관심목록은 별 버튼으로 관리하고 JSON 저장/불러오기로 보관한다. 일반 재열기에는 자동 보존하지 않는다. 앱의 데이터 새로고침으로 새 스냅샷에 전환할 때는 같은 탭의 임시 공간을 통해 필터·관심목록·보유 입력을 복원한다. 실제/가상 모드 또는 기업 식별이 달라지면 관심종목을 제외하고 알린다.

라이브 서버·CLI 내보내기는 같은 모드의 기존 공시/뉴스 캐시를 읽기 전용으로 연결한다. 공개 제목·출처·링크만 포함하고 기준일 이후 자료와 개인 검토 기록은 제외한다. 새 공시 수집·장기연구 관리는 기존 Streamlit 앱에서 수행한다. 보유 유지/매도 검토와 최대 5종목 포트폴리오는 기존 엔진을 사용한다.

전체 정의와 데이터 입력 방법은 [기업 발굴 명세](FUNDAMENTAL_DASHBOARD.md)를 참고한다.

네이버 PER/PBR·EPS/BPS는 `tools/naver_reference.py --codes <종목코드...>`로 명시한 종목만 1회 조회한다. 기업 간단 분석의 별도 보완 자료에 표시하며 주 분석 기준일·재무 기준과 섞지 않는다. 일반 데이터 새로고침 버튼은 네이버를 재조회하지 않으므로 수집 후 페이지를 다시 열어 새 참고 캐시를 읽는다.

코스피·코스닥 기업 발굴 범위는 `.venv\Scripts\python.exe tools\expand_market.py`로 명시적으로 1회 갱신한다. 공개 시장 목록·업종·완료 일봉을 `data/<profile>/market-expansion`의 Git 제외 캐시에 저장하며, 예약 실행이나 실시간 시세 연결은 하지 않는다. 재무 요약의 정확한 보고기간과 연결/별도는 원천 목록에 없어 참고 수치로 표시한다. 기존 인포맥스 기업은 검토된 값을 우선한다.

## 독립 HTML 결과물

`credit_dashboard_260929`의 상단 헤더·그룹별 좌측 메뉴·요약 카드·2열 차트 구성을 참고한 별도 결과물을 제공한다. 기존 Python/Streamlit 앱은 Infomax 저장자료 확인·갱신, DB와 연구 기능을 계속 담당한다. HTML은 내보낸 시점의 시장 스냅샷을 담은 독립 파일이다. 서버/API 없이 파일을 열어 메뉴, 필터, 차트 선택과 CSV를 사용할 수 있으며 새 데이터는 다시 내보내야 반영된다.

### 매일 쓰는 통합 화면

프로젝트 폴더에서 `.\.venv\Scripts\python.exe tools/serve_dashboard.py`를 실행하고 `http://127.0.0.1:8767/`을 연다. 이 화면은 같은 HTML 디자인을 사용하면서 시작 시 기존 `investment.auto_refresh.ensure_data()`로 마지막 정상 저장자료와 최신 여부를 확인한다. **데이터 새로고침** 버튼은 같은 갱신 함수의 강제 경로를 호출한다. 새 스냅샷이 저장되면 화면을 다시 표시한다. 원천 파일이 그대로면 날짜가 바뀌지 않으며 오래된 자료라고 표시한다. 연결 실패에도 마지막 정상 자료를 보여준다. 기본 주소는 이 PC의 127.0.0.1만 사용하고 예약 실행은 등록하지 않는다.

화면 안에서 입력한 보유·정책 값은 서버로 보내지 않는다. 새 자료로 화면을 다시 표시할 때 같은 브라우저 탭의 임시 저장공간으로 한 번 옮겨 복원한 뒤 즉시 삭제한다. 기업 식별 정보가 바뀌어 새 시장가격과 합칠 수 없으면 보유 입력을 보존하고 기존 가격으로 표시하며, 확인이 필요하다고 알린다. 장기성장·추세 연구와 공시·뉴스 관리는 기존 Streamlit 앱에서 계속 이용한다.

### 파일로 보관하는 결과물

- 앱 사이드바 **통합 HTML 대시보드 → HTML 결과물 만들기 → 통합 대시보드 HTML 다운로드**.
- CLI: `.\.venv\Scripts\python.exe tools/export_workspace.py`. 마지막 정상 실제 DB 스냅샷으로 생성하며 외부 데이터를 조회하지 않는다.
- 파일 위치: 각 PC의 `data_dir/<profile>/exports/investment_dashboard_YYYYMMDD.html`. 이름의 날짜는 가격 기준일이다. 생성 파일은 개인 데이터 디렉터리에 두고 Git에 올리지 않는다.
- HTML의 12개 메뉴: 통합 개요, 관측 가격 이력, 데이터바, 히트맵, 산점도, 조건검색, 기업분석, 산업비교, 보유 입력·검토, 평가손익, 포트폴리오, 원수치·산출 기준. 장기성장/추세 연구와 공시·뉴스 관리는 기존 Streamlit 앱에서 이용한다.
- 기업 비교의 시장·산업·검색 필터는 차트·요약·원수치·CSV에 동일하게 적용한다. 최대 30개 제한과 필터 범위를 표시한다. 기존 상세 조건검색은 자체 조건을 사용한다. 히트맵 셀·산점도 점·기업명을 누르면 선택 기업을 바꿀 수 있고, 상세 분석으로 연결된다.
- 내보내기에 기존 개인 보유 입력은 포함하지 않는다. HTML 안에서 보유 JSON을 직접 불러오면 기존 PortfolioEngine으로 검토하고 평가손익 화면에 반영한다. 개인 입력은 브라우저 메모리에서만 사용하며 별도 내보내기로 보관한다.
- 가격 이력은 상태·거래소·보정 기준이 명시된 관측만 표시한다. 없으면 대기한다. 차트의 수치와 기간은 기존 스냅샷을 그대로 사용한다.
- 데스크톱은 좌측 메뉴, 모바일은 상단 화면 선택 메뉴다. 히트맵·넓은 표는 내부 가로 스크롤을 사용한다. 현재 화면을 인쇄/PDF로 보관할 수 있다.

공통 소스는 `src/workspace.html`, `src/workspace.css`, `src/workspace.js`, 생성기는 `investment/workspace_export.py`다. 기존 상세 HTML을 내장해 분석 엔진을 재사용한다. 참고 파일의 채권 데이터·스크립트·라이브러리는 복사하지 않았다.
로컬 통합 화면 서버는 `investment/live_dashboard.py`, 실행 명령은 `tools/serve_dashboard.py`다.

## 인터랙티브 뷰어와 그래프

토스에서 볼 수 있는 밝은 회색 배경·흰 카드·파란 강조색·둥근 모서리의 시각 구성을 참고했다. 외부 폰트·이미지·CDN을 추가하지 않았다. 공통 테마는 `.streamlit/config.toml`, 화면 스타일은 `src/dashboard.css`다. 상세 HTML도 같은 색상을 사용한다.

- **범위:** 시장과 최대 30개 기업을 선택한다. 시장 변경은 해당 시장의 기업 선택을 다시 채운다. 기업 선택을 모두 지우면 빈 상태를 유지하며, 초기화로 전체 범위를 복구한다. 기본 30개 제한은 명시적으로 표시된다. 그래프·상세·CSV에 동일한 선택 범위를 적용한다. 조건검색 필터와는 독립이다.
- **데이터바:** 선택한 하나의 지표를 기업별로 비교한다. 수치는 원 단위/억원/%/배 등 표시된 단위를 따르며 축은 0에서 시작한다. 음수와 실제 0을 보존하고 결측은 제외 건수로 알린다. 파랑 그라데이션은 값의 크기다.
- **산점도:** X·Y 지표를 바꾸고 점을 클릭하면 하단 기업 상세가 연결된다. 두 값이 모두 있는 기업만 표시하며 유효 표본 수를 보여준다. 확대·축소와 툴팁을 제공한다. 업종으로 색을 구분하며 소수 표본에서 시장 상관관계를 추정하지 않는다.
- **히트맵:** 영업이익률·ROE·매출 증가율·부채비율의 셀 숫자는 원값이다. 색은 선택된 기업 안에서 지표별 `(값−최솟값)/(최댓값−최솟값)×100`으로 계산한다. 동일 값만 있으면 50, 결측은 회색이다. 높은 부채비율도 진한 파랑이므로 투자 품질·좋고 나쁨의 점수로 읽지 않는다. 필터마다 색 범위를 다시 계산한다.
- **가격선:** 상세 기업의 가격 기준일 이전 관측 종가만 사용하며 시점 툴팁·가로축 확대가 가능하다. 이력이 없으면 그래프 대기로 표시한다. 조정주가나 수익률을 임의 생성하지 않는다.
- **워터폴:** 오늘 화면의 보유 입력이 있으면 `주식 원가 + 종목별 평가손익 = 주식 평가액`을 표시한다. 기존 엔진의 유효 평가액·원가를 사용하고 현금·배당·실현손익·수수료는 제외한다. 10종목을 넘으면 절대 손익이 큰 10개 외 항목을 합산한다. 일부 보유의 가격·원가가 없으면 전체 차트를 보류한다. 이익은 빨강, 손실은 파랑, 합계는 회색이며 범례·툴팁으로 구분한다.

현재 PC의 실제 저장 스냅샷은 가격 이력이 비어 있으므로 가격선과 실제 보유 워터폴은 대기할 수 있다. 차트 정상 경로는 명시적 합성 자료로 별도 테스트한다.

## 매일 확인할 순서

1. 가격 기준일과 **먼저 확인할 항목**을 읽는다. 오래된 자료는 Infomax에서 조회·저장한 뒤 기존 **데이터 새로고침**으로 반영한다. 실제 단말 직접 조회는 아직 미연결이다.
2. **보유·연구 입력과 구성 설정**에서 기존 보유 JSON을 불러온다. 원본 파일과 DB를 수정하지 않고 현재 브라우저 세션에서만 사용한다. 실제 보유가 없다고 추측하지 않으며, 미입력과 명시적으로 빈 보유목록을 구분한다.
3. 필요하면 기업/산업/위험군 상한, 최소 현금, 하락 가정과 시나리오 손실 기준을 입력하고 설정을 확인한다. 이것은 개발 가정이며 실제 손실 상한이 아니다. 가격 기한 4일, 연구 검토 기한 120일은 기존 기본값을 사용한다.
4. 보유종목 판단과 최대 5기업 구성안을 확인한다. 후보별 부족 사유를 펼쳐 연구·가격·분류를 보완한다. 자료 부족이면 현금 100%나 임의 목표 비중을 만들지 않는다.
5. 공시·뉴스 표에서 원문을 열고, **기업분석** 메뉴에서 새로고침·검토 완료 표시를 한다. 삼성전자 뉴스룸과 설정된 DART 범위이며 전체 뉴스가 아니다.

## 화면과 입력의 범위

- 기업가격·뉴스는 현재 시장 스냅샷의 종목 범위다. 보유·편입 판단은 불러온 연구 종목과 시장 스냅샷을 병합한 범위다. 일일 요약은 조건검색의 시장/산업 필터와 독립이다.
- 편입 조건 충족 수는 기업별 연구·가격·분류 조건을 통과한 수다. 구성 설정 확인이나 산업/위험군 배분 상한까지 통과한 최종 편입 수와 다르다.
- 보유 검토 대기는 HOLD 이외 의견 또는 동일 기업 합산 비중 상한 초과 건수다. 매매 지시가 아니다. 사용자 입력 범위의 평가액만 계산하며 일부 가격·현금 결측이면 합계·비중은 산출 대기로 남는다.
- 뉴스 표는 미확인 주요 이벤트 우선, 발표일 내림차순으로 최대 10건을 보여준다. 전체 목록과 확인 버튼은 기존 기업분석 패널에 있다. 첫 카드에는 저장된 미확인 주요 이벤트 전체 건수를, 기업별 표에는 엔진 전달 한도인 최대 100건을 표시한다.
- 현재 세션에서 불러온 보유·연구 입력과 구성 설정을 **보유·포트폴리오** 상세 화면에도 연결한다. 상세 화면의 추가 편집은 별도 메모리 안에 있으므로 JSON으로 내보내 오늘 탭에서 다시 적용해야 일일 요약이 갱신된다. 화면 재실행 전에 내보낸다. 두 화면 간 실시간 양방향 편집이나 개인 입력 자동 저장은 지원하지 않는다.
- 세션을 닫거나 **일일 요약 입력 비우기**를 누르면 일일 입력을 사용하지 않는다. 새 브라우저 세션은 보유 미입력으로 시작한다. 실제·가상 모드는 분리하며 가상 화면에 실제 뉴스·보유를 전달하지 않는다.
- 실제 저장자료가 없는 PC는 기존 빈 화면과 업로드 안내를 유지한다. 가상 자료로 자동 전환하지 않는다.

## 기존 기능과 검증

기존 조건검색·기업분석·산업비교·A4·장기성장·추세·보유/포트폴리오·데이터 상태의 기능을 보존하고 오늘·인터랙티브 뷰어를 포함한 왼쪽 메뉴 10개로 구성했다. 선택 화면만 렌더링하고 조건검색·뷰어 필터와 세션의 보유 입력은 화면 이동 후에도 유지한다. 가격 저장과 보유·편입 판단 규칙은 그대로 사용한다.

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_daily_dashboard
$env:INVESTMENT_TEST_URL='http://127.0.0.1:8501'
.\.venv\Scripts\python.exe tests\test_daily_ui.py
.\.venv\Scripts\python.exe -m unittest tests.test_visuals
.\.venv\Scripts\python.exe tests\test_viewer_ui.py
```

두 번째 검사는 실행 중인 로컬 대시보드를 사용한다. 합성 종목·수량을 해당 검사 브라우저 세션에만 올려 정상/잘못된 입력, 설정 연결, 상세 일치, 세션 분리, 좁은 화면을 검사한다. 사용자 실제 보유 검증과 구분한다. 테스트 결과와 실제 저장자료 확인은 PROJECT_STATE.md에 기록한다.
