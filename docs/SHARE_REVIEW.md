# 두 PC 코드 인계 후보 · 2026-09-28

사용자는 이 프로젝트가 일반 상장기업 데이터와 개인 관심 기록이며 회사 감사·반출 승인이 필요한 민감자료가 없다고 확인했다. 따라서 회사 반출 심사는 인계의 대기 조건이 아니다. 토큰·비밀번호 및 각 PC의 로컬 설정·DB는 별도로 둔다.

## 현재 후보

`config/share_candidates.json`에 실행·검증·기존 작업 맥락에 필요한 91개 파일을 명시했다. 원본 `README.md`와 `PROJECT_STATE.md`를 그대로 포함한다. 이전에 작성한 PORTABLE_README/PORTABLE_PROJECT_STATE는 후보에서 사용하지 않는다. 실제 데이터베이스, 로컬 설정, 출력 로그, 전체 세션, 기존 dist ZIP, 사용자 제공 연구 원문은 파일 목록에 없다. HTML 출력은 포함하며 소스로 다시 빌드할 수도 있다.

`tools/validate_share_candidates.py`는 91개 파일의 경로·UTF-8·인증정보로 보일 수 있는 URL·개인키 헤더를 점검하고 임시 `home` 프로필로 실행한다. 파일 검사 결과는 지정 패턴 0건이다. `.invalid` 도메인의 합성 URL 둘은 인증정보 거부 테스트의 입력으로만 사용한다. 검사는 개인 관심 종목 코드나 공개기업 재무 수치를 민감자료로 취급하지 않는다.

임시 대상에서 HTML 빌드, Python 연구/앱 테스트, JS 엔진/포트폴리오 테스트, 가상 데이터 일간·주간 계산, 실제 데이터가 없을 때 빈 상태 표시를 확인했다. 회사 PC 실제 저장자료 모드도 8개 탭과 실제 자료 표시를 확인했다. 이는 집 PC에서 직접 실행한 결과가 아니다. 세부 출력은 `validation/current/share-candidate-review.json`과 `share-test-*.txt`에 있다.

## 원격 상태와 다음 단계

이 PC의 GitHub CLI는 `shinyj0270-afk`에 로그인되어 있다. 사용자가 `shinyj0270-afk/invest` 공개 저장소를 이 프로젝트의 원격으로 확인했다. 처음에는 빈 저장소였고, 기존 작업폴더에 Git `main`을 만든 후 91개 명시 파일을 커밋·전송했다. 최초 커밋 `796343f121254165bc184c4ed9be7cc6fd79e697`과 후속 상태 문서 커밋을 전송했다. 작업 마감 때 원격 `refs/heads/main`과 로컬 HEAD 일치를 `git ls-remote`로 확인했다.

집 PC의 수신·실행은 아직 확인하지 않았다. 그 PC에서 기존 작업본부터 확인하고 같은 `main` 커밋을 받은 뒤 home 설정으로 가상 앱을 실행해야 한다.
