# 저장자료 갱신

## 매일 하는 일

1. 인포맥스에 로그인한 상태에서 기존 일별 Excel 파일을 열고 조회 종료일·조회 결과가 원하는 날짜인지 확인한 뒤 **저장(Ctrl+S)** 한다. 함수 계산과 조회가 끝난 뒤 저장한다.
2. 앱의 **실제 저장자료 → 저장 파일로 갱신**을 누른다.

파일 검증, 가격·수급 계산, 로컬 저장, 일간·주간 목록 반영을 한 번에 처리한다. 이미 공개 추세 시세가 연결된 PC에서는 **새 가격일에만** 세 종목과 KOSPI 공개 시세도 다시 조회·검증한다. 다른 이름으로 내보낼 필요 없이 설정된 파일을 계속 사용한다. 버튼 아래에서 마지막 완료 시간, 저장 파일 조회일, 가격일을 확인한다. 당일 관측은 제외하므로 가격일과 조회일은 다를 수 있다.

Excel 저장만으로 인포맥스 조회가 갱신되지는 않는다. 앱은 저장된 계산 결과를 읽는다. 원본 파일을 조회·저장하지 않으면 `파일 변경 없음`으로 표시하고 기존 자료로 목록을 확인한다. 성공 시간은 로컬 처리 완료 시간이며 새로운 시장자료 수신을 뜻하지 않는다.

## 재무자료와 오류

- 재무는 기존에 검토한 기간·원자료·공식 보고서 대조 결과를 유지한다. 새 분기 재무 연결은 별도 원자료 검토가 필요하다. 일별 갱신으로 재무 조회일을 바꾸지 않는다.
- KRX 사용자 지정 기준, 잠정값 허용, 최근 20개 공통 관측일 사용 정책이 적용된다.
- 입력 오류·과거 파일·종목 구성 변경은 반영을 중단하고 기존 저장자료를 유지한다.
- 자료 저장 이후 목록 계산이 실패하면 `추세/목록 갱신 일부 실패`로 표시한다. 동일 버튼을 다시 누르면 목록 계산을 재시도한다.
- 공개 추세 시세 조회가 실패하거나 날짜가 인포맥스 가격일과 맞지 않으면 일별 자료는 저장하고 `추세/목록 갱신 일부 실패`로 표시한다. 오래된 추세로 새 가격일을 판정하지 않는다. Excel 파일을 다시 저장하지 않고 같은 버튼으로 재시도할 수 있다. 원본 공개 응답은 PC 로컬 데이터 폴더의 `trend-source/<가격일>/`에 해시별로 보존한다.
- 재시작 후에도 최근 결과가 표시된다. 실행 중 PC가 종료되어 잠금이 남았다면 실행 중인 갱신 작업이 없는지 확인한 뒤 해당 PC/모드의 `refresh.lock`만 제거한다.

## PC별 최초 설정

각 PC의 Git 제외 파일 `config/local.json`에 아래 경로를 설정한다. 프로젝트 루트 기준 상대 경로나 이 PC의 절대 경로를 사용한다. `profile`, `data_dir`, `enabled_data_adapters`는 기존 PC별 설정을 유지하며 `infomax_manual`이 허용되어 있어야 한다.

```json
{
  "infomax_refresh": {
    "daily_file": "private_data/infomax/daily.xlsx",
    "company_config": "private_data/infomax/daily-config.json",
    "policy": "config/infomax.user-decisions.json"
  }
}
```

종목 설정은 기존 일별 변환기 계약을 사용한다. 정책은 공통 정책 JSON에서 매번 읽는다. 최초 기준 자료는 기존 DB 또는 `manual_snapshot_file`로 연결되어 있어야 한다. 갱신 후 앱의 기준은 DB이며, `manual_snapshot_file`은 DB가 없는 PC의 최초 연결용이다. DB를 임의로 지우면 최초 자료로 돌아갈 수 있다.

갱신 스냅샷은 데이터 폴더의 `<profile>/user_input/refresh-snapshots/`에 보존한다. 원본 Excel, 재무 원자료, 기존 DB 스냅샷을 덮어쓰지 않는다. 갱신 기록은 같은 DB의 설정에 저장한다. 원자료·DB·설정·스냅샷은 자동 공유하지 않는다.

앱 대신 동일 작업을 실행할 때:

```powershell
.\.venv\Scripts\python.exe tools/refresh_infomax.py
```

예약 작업이나 Windows 자동 시작 등록은 이 절차에 포함하지 않는다.
