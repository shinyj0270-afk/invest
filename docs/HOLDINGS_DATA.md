# 보유종목 판단과 저장 시장자료 연결

실제 저장자료 모드의 **기존 보유·포트폴리오** 탭이 현재 스냅샷의 종목·관측 종가·가격일·출처를 기존 보유 판단 엔진에 전달한다. 보유 수량·매입가·현금은 자동 생성하지 않는다. 직접 입력하거나 기존 보유 JSON을 가져온다. 입력은 iframe 메모리에만 남으므로 대시보드 갱신 전에 JSON으로 내보내고, 다시 열면 그 파일을 가져온다.

`investment/holdings_bridge.py`는 기존 시장 스냅샷을 보유 입력 계약으로 변환한다. `PortfolioEngine.attachMarket`은 가져온 보유 입력에 가격을 연결하면서 수량·매입가·현금·투자 논리·검토 근거를 유지한다. 더 오래된 날짜의 시장가격으로 사용자의 새 가격을 덮어쓰지 않는다. 같은 날짜는 명시적으로 입력한 수기 가격을 유지하고, 그 외에는 연결 스냅샷 값을 반영한다. 더 최신인 시장 관측 가격은 갱신한다. 종목 식별 정보가 다르면 적용을 거절한다. 가상 예제에는 실데이터를 섞지 않는다.

가격은 `meta.price_date`와 일치하는 `companies[].prices`의 관측 종가만 사용한다. 날짜 없는 `metrics.price`를 가져오거나 없는 가격을 추정하지 않는다. 로컬 스냅샷 SHA-256을 가격 출처로 기록하며 거래소·확정 여부·보정 상태를 표시한다. 로컬 파일을 웹 URL로 가장하지 않는다.

평가일은 현재 한국 날짜이며 기존 엔진의 가격 기한(기본 4일)을 적용한다. 오래된 가격은 평가금액·손익·비중 계산에 사용하지 않는다. 일부 가격이 없으면 남은 종목 비중을 100%로 다시 계산하지 않는다. 가격이 있어도 투자 논리·사업·재무·가치평가·위험 검토와 근거가 없으면 **판단 보류**다. 재무 비율만으로 `HOLD` 또는 `SELL`을 채워 넣지 않는다.

이번 2단계는 실제 저장 가격을 기존 보유 엔진에 연결하고 결측·오래된 가격 처리와 사용자 입력 보존을 확인하는 범위다. 실제 사용자 보유 수량과 검토 근거가 없는 상태에서 실행한 샘플 수량은 검증용이며 실제 보유·매매 판단으로 보고하지 않는다. 최대 5종목 포트폴리오 엔진 실데이터 검증은 다음 3단계다.

## 직접 추가 후 수치 표시 · 2026-10-01

1. 종목코드·수량·평균 매입가를 입력한다. 연결된 코드는 목록에서 선택할 수 있다.
2. 연결 가격이 없으면 **현재가·가격 기준일·출처**를 입력한다. 임의 테스트 가격은 출처에 **가상 입력**이라고 적는다. 실제 종가를 조회한 것처럼 표시하지 않는다.
3. **현금**도 함께 입력하고 **보유·가격·현금 반영**을 누른다. 현금이 없으면 **0**, 모르면 빈칸으로 둔다. 현금만 바꿀 때는 별도 현금 반영 버튼도 사용할 수 있다.
4. 매입금액·평가액·평가손익·수익률을 확인한다. 모든 보유종목 가격과 현금이 확인되면 전체 평가액과 비중이 계산된다. 매입가가 없으면 해당 종목 손익만 계산 대기다. 누락 항목과 오래된 가격은 표와 아래 안내에 표시한다.
5. 기존 행의 **입력 수정**으로 수량·매입가·가격을 불러와 수정한다. 종목코드를 바꾸면 이전 종목의 입력칸을 비워 가격 혼입을 막는다.

수기 출처는 `price_source.kind=manual_input`과 사용자 출처명을 기록하며 웹 URL은 선택 사항이다. URL이 있으면 http(s) 형식과 인증정보 포함 여부를 검사한다. 가격은 양수, 기준일은 정확한 날짜이며 입력 평가일 이하여야 한다. 잘못된 입력은 저장된 보유·현금·가격을 보존한다. 평균 매입가를 현재가로 사용하지 않는다.

연결되지 않은 기업에 수기 가격을 넣어도 기업 정체·연구 상태·검토 근거는 미확인으로 남는다. **가격 계산이 가능해도 기업 의견·모의 목표안은 판단 보류일 수 있다.** 세 화면은 같은 가격 경과일 설정을 사용한다. 이 기능은 시세 자동 조회를 추가하지 않는다.

기존 화면의 입력은 메모리에 있으므로 **입력 내보내기** 후 새 HTML을 열어 **불러오기**로 복원한다. 열린 화면을 새로고침하면 내보내지 않은 입력이 제거된다.
